## Theme: SwiftUI observation & render performance

- **`@Published` dictionary caches on a shared model republish the WHOLE observable tree.** A per-tab `highlightCache` on `DocumentModel` caused every tokenize-complete to re-eval all UI. Fix: per-tab actor (`HighlightCacheActor`) with its own `@Published var version`, held in a plain non-`@Published` dict — consumers observe the actor directly, narrowing re-eval to the tab's subtree. — UNIVERSAL (architecture pattern) · carry-forward: PORT
- **SwiftUI OVER-OBSERVATION is the dominant perf trap in this codebase.** A view holding `@ObservedObject var model: BigModel` re-bodies on every model republish; always-on-screen views (sidebar, status bar) re-bodied per keystroke/scroll-tick (249× baseline in one measured case). Fix pattern: narrow-channel `ObservableObject`s per concern (`SourceViewChannel`, `FindCoordinator`, `PanelLayoutStore`) instead of one god-model. — UNIVERSAL · carry-forward: PORT (design principle)
- **A `@StateObject`/timer placed on a SwiftUI PARENT re-bodies the whole parent every tick.** Extract the timed thing into its own child view that owns the `@StateObject`; also change-gate `@Published` values (fires on every assignment, not just on change). — UNIVERSAL · carry-forward: PORT
- **Never do filesystem I/O in a SwiftUI `body` getter** (git-root discovery walked ~64 `fileExists` per sidebar redraw). Cache and recompute only on the triggering event. — UNIVERSAL · carry-forward: PORT
- **A layout-driving `GeometryReader` that writes `@State` it then re-reads is a per-frame layout-pass multiplier** — live-only, invisible to a one-pass headless harness. Use non-layout `.background(GeometryReader)` + epsilon-guard state writes. — UNIVERSAL · carry-forward: DISTILL
- **A cache a SwiftUI `body` reads read-only to DECIDE WHETHER A SUBTREE EXISTS becomes part of the view lifecycle** — evicting an entry is equivalent to tearing the view down. Eviction policy must be mounted-aware / aligned with the subtree's retention policy (rendered-HTML cache vs `MountedPanesLRU`). — UNIVERSAL · carry-forward: PORT

## Theme: WKWebView / NSViewRepresentable retention & compositing

- **Retain inactive WebView panes at `.opacity(0)` + `.allowsHitTesting(false)` + `accessibilityHidden` — never `.hidden()`.** `.hidden()` removes the view enough that WebKit fires `visibilitychange` and self-reloads (kills the retention benefit). This was the dominant fix for a 2–9s tab-switch freeze. Validate the no-remount invariant with a DEBUG probe counting `makeNSView`/`dismantleNSView`. — UNIVERSAL (WKWebView-specific but broadly relevant) · carry-forward: PORT
- **An opaque, layer-backed `NSViewRepresentable` OCCLUDES a SwiftUI sibling drawn before it** — position/paint-order dependent, NOT overlap-dependent. A representable becomes a real AppKit subview with its own `CALayer` that composites over earlier-painted SwiftUI siblings even when geometrically adjacent. Fix: give each sibling its own compositing layer with explicit z-order (`.compositingGroup().zIndex(N)`) in every layout branch. Cost 4 wrong-fix rounds before diagnosis (see false-green tool matrix below). — UNIVERSAL (SwiftUI+AppKit hybrid apps) · carry-forward: PORT (both the bug pattern and the fix idiom)
- **`ImageRenderer`/`cacheDisplay`/headless frame-walks give a FALSE GREEN for representable-occlusion bugs.** `ImageRenderer` rasterizes SwiftUI's own tree in isolation and draws a placeholder for the representable — no opaque layer to occlude. `cacheDisplay` is blind to SwiftUI CA layers. The ONLY authority is real WindowServer pixels (`screencapture -l<windowID>`). — UNIVERSAL · carry-forward: PORT (test methodology)
- **`MarkdownRenderedView` (NSViewRepresentable) can't be unit-driven** — `NSViewRepresentable.Context` isn't publicly constructible. Validate its bridge logic at the model layer + a JS round-trip against the actual rendered page. — PROJECT-SPECIFIC · carry-forward: DISTILL

## Theme: WebView/CM6 bundling & JS bridge hazards

- **CodeMirror peer-dep version floor silently dup-bundles → blank editor.** Pinning `@codemirror/state` below a peer's declared floor let npm nest a second copy; esbuild bundled both; `instanceof` checks broke; CSP swallowed the error to generic "Script error." with nothing surfacing in-app. Fix: satisfy every peer-dep floor when bumping any `@codemirror/*` package; a CI check counting `node_modules` copies of a package would catch it (not yet built). — TOOLING/HARNESS · carry-forward: DISTILL
- **`JSONSerialization.data` doesn't escape U+2028/U+2029** (valid JSON chars AND valid JS line terminators) — embedding JSON into `evaluateJavaScript("...\(json)...")` breaks the bundle parse silently. Central sanitizer (`JSStringEmbedding.sanitize`) used by every bridge JSON route. — UNIVERSAL · carry-forward: PORT
- **CSP `style-src 'unsafe-inline'` is allowed by default in recent WebKit for `loadHTMLString`-loaded documents** — CSP is not sufficient HTML-injection defense; an explicit tag/attribute/URL-scheme allowlist sanitizer is required, CSP is defense-in-depth only. — UNIVERSAL (security) · carry-forward: PORT
- **`evaluateJavaScript`/WebView tests: async continuation needs `Task.sleep` polling, not `RunLoop.current.run(until:)`** in an async `@MainActor` test — a sync RunLoop blocks the main actor so the off-main render's republish continuation never lands, and the WebView never mounts (looks like a SKIP, not a fail — always grep the per-test passed/skipped line). — TOOLING/HARNESS · carry-forward: DISTILL

## Theme: Data/text/encoding correctness

- **`Data.subdata(in:)` after `removeFirst(n)` returns garbage on macOS 26** — slice-offset state isn't surfaced consistently. Workaround: rebuild via `[UInt8]` (`Data(Array(data)[..<n])`) for a canonical view with no offset state. — TOOLING (platform bug) · carry-forward: DISTILL (watch for on future OS versions)
- **`FileHandle.read(upToCount:)` + `write(contentsOf:)` concurrently on the same `Pipe` wedges writes after 1-2 messages** — Cocoa's I/O layer serializes through a shared kqueue source. Fix: raw POSIX `read(2)`/`write(2)` on fds, reader on a dedicated `Thread` (not `Task.detached` — blocking read starves the cooperative pool), `F_SETNOSIGPIPE` on the write end. — UNIVERSAL (subprocess/pipe IPC) · carry-forward: PORT
- **`FileHandle.fileDescriptor`/`.availableData` accessors raise an UNCATCHABLE ObjC exception when the handle is closed under a blocked reader** — `try?`/`catch` cannot catch it; even a raw `Darwin.read` doesn't dodge it because the accessor itself throws before the syscall. Fix: cache the fd ONCE at reader init while open, then use the cached fd for `read(2)`; external close → EBADF → treat as EOF. — UNIVERSAL · carry-forward: PORT
- **Grapheme (Swift `Character`) vs Unicode-scalar (Rust `char`) index domains diverge on combining marks/ZWJ emoji** — any string-index-emitting code (fuzzy-match highlight ranges) claiming byte-exact Swift/Rust parity needs a grapheme-segmentation crate or the parity claim is dishonest for non-ASCII input. — UNIVERSAL (cross-language porting) · carry-forward: PORT (hazard checklist item)
- **Recursive-descent parsers on untrusted structured input need an explicit depth cap** — deep nesting (`[[[[…]]]]`) overflows the stack and *aborts the whole process* under `panic="abort"`, not even catchable. Same class as a cmark deep-nesting SIGSEGV found in audit. Cap at ~128 (matches `serde_json` default), degrade to raw-text fallback. Teeth: test on BALANCED valid deep input (only the cap can reject it), neuter the cap and confirm SIGABRT, restore. — UNIVERSAL (security/parser hardening) · carry-forward: PORT

## Theme: Rust-core migration — the repeatable template

- **The Type-1 stateless FFI slice migration template** (6 steps): (1) pure core fn in Rust with parity tests incl. hazards (UTF-16/astral/CRLF/OOB); (2) wire seam via `wire::{decode_frame,encode_frame}` (u32-LE + rmp msgpack) for structured results; (3) FFI shim (`ffi_guard!`, out-`MdvBuf`, `MdvStatus`, cbindgen regen); (4) Swift bridge via hand-rolled MsgPack encoder/decoder; (5) ViewerCore adapter behind a default-OFF capability gate falling back to Swift on any bridge fault; (6) A/B parity test forcing the Rust path and asserting byte-equal vs Swift over a hazard corpus. Never delete the Swift path until the slice has soaked ON. — UNIVERSAL (this IS the target architecture for the next project) · carry-forward: PORT (verbatim — this is the exact migration recipe the greenfield project should reuse from day one, skipping the "migrate later" phase)
- **Wire-frame vs raw-bytes-out decision rule:** structured results ride a MessagePack frame; a BIG single string/blob (hex dump text, large inputs) crosses as raw bytes via pointer+len — wrapping+re-decoding a huge blob would double the cost for nothing. — UNIVERSAL · carry-forward: PORT
- **"One core, three front-ends" (SwiftUI/TUI/web) works and stays honest via a shared render-agnostic view-model** (`core::view::build(bytes,name,mode) -> {Text|Hex|Table}+modes`) — front-ends become thin renderers that can't drift; front-end bins kept OUT of the merge gate + app bundle via `default-members` in the workspace Cargo.toml. — UNIVERSAL (directly matches the greenfield goal: Rust core + Swift/TUI/web/remote transport) · carry-forward: PORT
- **A configured `[workspace.lints]` deny is a dead letter if CI never runs `cargo clippy`/`cargo test` on it** — real panic sites shipped despite denies because CI only ran `cargo build`. Verify the lint/test config is actually INVOKED by a gate, not just present. — TOOLING/HARNESS · carry-forward: PORT (as a CI checklist item)
- **rust-core is sans-IO BY DESIGN (no fs/process) for WASM-portability** — IO (file reads, git spawn) stays in front-ends; only pure logic + security-critical constants move into core. Audit findings suggesting "hoist into core" must be checked against this boundary first. — UNIVERSAL (architecture decision, directly reusable) · carry-forward: PORT
- **rust-core has TWO parallel property-test styles that both count** — a long-standing DIY xorshift fuzz lane (`*_fuzz_*`, seeded, `MDV_FUZZ_SEED_BASE` for nightly sweep) AND the `proptest!` macro lane; check for BOTH before assuming an engine lacks property coverage (a redundant proptest was added and reverted after missing the DIY lane). — TOOLING/HARNESS · carry-forward: DISTILL
- **Differential fuzzing of dual-twin (Swift+Rust gated) engines found 4 real bugs the per-engine tests missed**, all clustered in COERCION/FORMATTING/OPERATOR-COMPLETENESS, not core algorithm logic. Pair every parity fuzz with a toggle-teeth test proving the env-var actually switches engines (else it's a vacuous green hitting the same engine both times). Scope out documented divergences (regex dialect differences, grapheme-vs-scalar offsets) or you chase non-bugs. — UNIVERSAL (test methodology for dual-implementation migrations) · carry-forward: PORT
- **`swift test --filter` does NOT relink the Rust-core `.a`** — it's an `-L` dependency, not a tracked SwiftPM input; only a full clean `swift test --parallel` reliably relinks. Later hardened further: **rebuilding the `.a` does not even trigger relink at all** — SwiftPM doesn't track the external staticlib's mtime, and even `touch`ing bridge Swift files only forces recompile, not relink, when the resulting objects are byte-identical (silently ships stale Rust code with a "Build complete" false-positive). Durable fix: `build-rust-core.sh` deletes SwiftPM link products whenever the staged `.a` content changes; `build-app.sh` hard-fails on stale-link. Long-term fix: xcframework binaryTarget makes the `.a` a tracked input natively. — UNIVERSAL (FFI/native-lib build-system hazard) · carry-forward: PORT (the detection + xcframework recommendation, verbatim)
- **Adding an enum case breaks EVERY front-end's exhaustive match** — expected, mechanical, but budget for it in "one core, N front-ends" designs; a stale/fast "Finished" `cargo build` can mask a downstream E0004 (force recompile with `touch`/`--workspace`). — UNIVERSAL · carry-forward: DISTILL
- **`cargo-deny` unions ALL platforms' dep graphs by default** — most "duplicate version" findings can be windows/linux-only phantoms; pin `[graph] targets` to actually-built triples for real findings. **`cargo-deny` 0.18.x can't parse CVSS-4.0 advisories** — split duties: deny owns licenses/bans/sources, cargo-audit owns advisories. — TOOLING/HARNESS · carry-forward: PORT
- **`cbindgen` does not expand `macro_rules!`** — extern "C" signatures must stay hand-written in scanned source or they vanish from the header silently; a header-drift check catches it but you must design signature-generation around this. — TOOLING/HARNESS · carry-forward: DISTILL
- **rust-core clippy denies cheat-sheet:** `indexing_slicing` (use iterators/`saturating_sub`), `Instant::now`/`SystemTime::now` banned in core (inject a Clock port), `unwrap/expect/panic` banned in non-test code, one-unsafe-op-per-block, `collapsible_if` (edition-2024 let-chains), `gen` reserved in edition 2024. — PROJECT-SPECIFIC (but the discipline is UNIVERSAL) · carry-forward: PORT (the discipline, not the exact list)

## Theme: SwiftPM / build staleness traps (a recurring class, ~8 distinct instances)

- **Adding a defaulted parameter to a public func/init changes its mangled symbol; SwiftPM's incremental compiler won't recompile callers that omit the new arg** → link error ("Undefined symbols") even after a full `swift build`. Fix: `grep -rl` the symbol across Sources+Tests and `touch`, or (more robust) add a SEPARATE init with distinct required labels instead of a defaulted param on the existing one — no symbol churn at all. — UNIVERSAL (Swift-specific but the "additive API breaks stale objects" class is universal) · carry-forward: PORT
- **Cross-module enum-layout skew (adding a case) leaves stale test objects compiled against the OLD tag order** — cross-module `==` silently evaluates false, or a pattern-match on a stale `.o` SIGSEGVs on a from-scratch `throw` with no FFI involved (looks exactly like an FFI/unwinding bug). `touch` the dependent files, INCLUDING Tests/ targets, not just Sources/. — UNIVERSAL · carry-forward: PORT
- **SwiftPM does NOT track a prebuilt static lib (`.a`) as a build input** — rebuilding it alone does not relink dependent test bundles (see rust-core section above; this is the general Swift/native-lib version of that hazard). — UNIVERSAL · carry-forward: PORT
- **A products-clean full recompile can expose a compiler bug an INCREMENTAL build was masking** (a recursive `Equatable` enum hit a Swift 6.1.2 type-checker "circular reference" only on clean build) — different toolchain versions can differ on strictness; select the newer toolchain explicitly rather than relying on the default. — TOOLING/HARNESS · carry-forward: DISTILL

## Theme: Multi-agent / workflow orchestration hygiene (large, recurring section — directly relevant to how the greenfield project will likely be built)

- **The shape that worked for large fan-outs:** scope → parallel review/fan-out → triage (dedup + partition into FILE-DISJOINT fix groups + a surface-only queue) → fix (worktree-isolated, self-verify build+tests) → orchestrator merges green branches with `git merge --no-ff` + runs the combined gate. Design phases used a judge-panel (N angled proposals → 1 synthesis). — UNIVERSAL (process pattern) · carry-forward: PORT
- **Worktree-pruning + uncommitted-work-loss:** the harness may prune an agent's worktree on completion; if the agent didn't commit, mutations survive only in the PARENT repo's working tree (shared filesystem), and the agent's claimed branch may not exist as a ref. Mitigation: brief agents to commit incrementally, not at the end; verify with `git status`/`git log --all` before assuming loss. — TOOLING/HARNESS (specific to this harness's worktree semantics) · carry-forward: PORT (as a standing operating discipline)
- **Agents ignore "only touch your files" and sweep unrelated files via broad `git add -A`** — brief with an explicit allowlist AND verify each branch's `git diff --name-only` against its assigned set before merging. **File-disjoint triage is not actually guaranteed** — two groups can independently edit the same file and only survive because hunks didn't overlap; always run a cross-branch collision check before merging: `for b in <branches>; do git diff --name-only main..$b; done | sort | uniq -d`. — TOOLING/HARNESS · carry-forward: PORT
- **Auto-fix agents can stray into surface-only/one-way-door items they were told NOT to implement** — the test/CI gate does not cover packaging/signing paths, so a broken signing change passed `swift build`+`swift test` and only broke on a real distribution build. Re-verify the diff of any group that was near a flagged one-way-door. — UNIVERSAL (agent-autonomy guardrail) · carry-forward: PORT
- **Advisory `blockers[]` fields in agent JSON output are routinely conflated with "red" by orchestration guard scripts** — agents put informational notes there too. Gate the pass/fail decision strictly on `build_clean && tests_pass`, treat `blockers[]` as informational. — TOOLING/HARNESS · carry-forward: PORT
- **zsh does NOT word-split an unquoted scalar in a `for` loop** (unlike bash) — use a real array (`order=(33 34 35)`) for merge-order loops. — TOOLING · carry-forward: DISTILL
- **Don't gate a TORN (mid-run) worktree** — sequential edit-only agents write incrementally, so a `git diff` taken before the workflow's completion notification can show only a prefix of the final change. Rule: gate the COMMITTED commit, not a live worktree snapshot — wait for the completion signal, or commit first and re-gate that exact tree. — UNIVERSAL (this is the single most load-bearing process lesson in the file) · carry-forward: PORT
- **Squash-merge (not per-commit rebase) for long-divergent branches** — resolve conflicts ONCE against the final tree; per-commit rebase re-conflicts at every commit. — UNIVERSAL · carry-forward: PORT
- **`swift build` (or any compile-only check) does NOT compile tests** — a merge can be build-green yet test-compile-broken; always run the test-compile step after a merge that removes/renames API. — UNIVERSAL · carry-forward: PORT
- **Cascading conflicts: merge branch order matters** — sequence overlapping-file branches cheapest-first or accept the later ones balloon in conflict size. — UNIVERSAL · carry-forward: DISTILL
- **Reconciling a stale branch (163 commits behind):** don't blanket-merge or blanket-drop — `git diff branch...main` per file + grep each key symbol in main to classify every hunk as already-landed / superseded / genuinely-missing; salvage only genuinely-missing non-contradictory pieces. — UNIVERSAL · carry-forward: PORT
- **Workflow/agent self-reports LIE — reconcile against git/disk ground truth, always.** A workflow claimed "0 fixes landed, 32 staged on branches"; reality was 2 landed, ~27 uncommitted in worktree dirs (not committed to branches at all). Never act on an agent summary for landing/reaping without checking `git log`, `git status` per worktree, and tree-diffs yourself. — UNIVERSAL (repeats the memory-file lesson `feedback_workflow_central_gate`) · carry-forward: PORT
- **A schema-bound agent that ends without calling its structured-output tool aborts the WHOLE workflow if awaited bare** — wrap each schema agent in try/catch (record sentinel + continue); mandate in the prompt "your LAST action MUST be the structured output call, even for empty results" + a scope guard against context-exhausting work. — TOOLING/HARNESS · carry-forward: PORT
- **Multi-agent fix fleets leave fixes UNCOMMITTED in worktree dirs sharing one object DB** — cross-worktree `git stash` mispops can leave `RECOVERED-*-belongs-to-sibling` entries. Harvest procedure: commit each worktree to its own branch FIRST (verify commits>0/dirty=0), THEN remove the worktree. — TOOLING/HARNESS · carry-forward: PORT
- **Before any mass branch/worktree cleanup: `git bundle create --all` first** (capture stashes as temp branches so they're included), verify the bundle, THEN delete freely — one file = total recoverability. — UNIVERSAL · carry-forward: PORT
- **`ahead=N` (rev-list), not tree-diff, is the "does this branch have unique value" signal** once main has moved far ahead (every stale branch's raw tree-diff becomes noise). Confirm files-unique-to-branch with a `comm` diff before deciding land-vs-delete. — UNIVERSAL · carry-forward: PORT
- **Piping/tailing a test run's output HIDES the true gate verdict** — a heavy-tier tier-policy sentinel failure can read as green for many commits when `| tail -N` clips the failure banner (printed after the last per-test line). Always trust the gate's own exit code, or grep for the specific failure banner text, never a tailed/piped view. This bit multiple times across the session log (`;`-chained `git commit` after a remote build committed even on build FAILURE for the same reason). — UNIVERSAL (repeated, high-severity CI hygiene lesson) · carry-forward: PORT
- **Session-usage limits kill agent fleets mid-flight — worktrees are the salvage net.** A 9-agent fleet died on session limit with zero structured results returned, but every worktree survived with real commits + uncommitted WIP. Salvage: `git worktree list` → per-worktree `git log main..HEAD` + `git status` → commit WIP to its branch → reap dirs, keep branches. Corollary: don't launch big fleets near a limit window; single sequential agents fail smaller/more gracefully. — UNIVERSAL · carry-forward: PORT
- **The main loop and an inline (non-worktree) subagent SHARE the git index** — a main-loop commit while an inline agent has files staged swallows the agent's staging. Rule: zero main-loop repo writes while an inline agent runs; worktree-isolated agents are immune. — TOOLING/HARNESS · carry-forward: PORT
- **Scale note:** a 47-agent pre-launch audit ran ~6.5M output tokens (516-agent deep-audit run ~26M tokens and tripped the account's monthly spend limit). Justified for genuine pre-launch/deep audits; do not reach for 40+-agent fan-outs for routine work. — UNIVERSAL (cost governance) · carry-forward: PORT

## Theme: VM / CI test-infrastructure (large section, mostly project-specific mechanics but with universal principles)

- **A `killall <exec-name>` in any test/build script is a footgun if the shipping app shares its executable name with test-spawned instances** — it will SIGTERM the developer's actually-running app. This bit at least 3 separate call sites over the project's life (`AppLauncher`, `install-app.sh`, more). Fix pattern: tag every test spawn with an env marker (`MDV_TEST_INSTANCE=1`), kill by reading each candidate PID's environment (`ps eww -p <pid>`) and matching the marker — never a blanket `killall`. — UNIVERSAL (recurring, high-owner-impact bug class) · carry-forward: PORT (the pattern, verbatim)
- **A local-only VM/CI cross-compiler-version skew is a REAL forward-compat signal, not noise** — the VM's stricter Swift toolchain caught genuine actor-isolation bugs the host toolchain waved through. Treat a stricter secondary environment's errors as real, not "environment drift." (Directly connects to the corrected "9-day env-drift dismissal masked a real product bug" lesson — a deterministic failure dismissed as environment drift deserves a 5-minute probe before being normalized into the gate, every time.) — UNIVERSAL · carry-forward: PORT
- **`ulimit -n` under a non-login ssh session (256) causes false EMFILE failures on a large test suite** — bump to a much higher hard limit before large test runs. — TOOLING/HARNESS · carry-forward: DISTILL
- **Tests run outside a real GUI/Aqua session cannot realize windows** — any live-app/pixel-capture test tier needs to run INSIDE a console-user GUI session (`launchctl asuser`-style bridging), not over plain ssh. Screen-capture TCC grants attach to the RESPONSIBLE PROCESS (the test runner), not an ancestor shell — granting `/bin/bash` doesn't help if the actual spawning process is a different binary. — UNIVERSAL (macOS UI-testing infrastructure) · carry-forward: DISTILL
- **A stale `dist/` build artifact silently invalidates live-app validation** — a build/deploy script that doesn't rebuild the artifact before a UI test spawns a month-old binary and produces false "regression" reports. Always check artifact mtime against the fix's timestamp before trusting a live-app test result. — UNIVERSAL · carry-forward: PORT
- **A hung/orphaned single-process test run can hold a build-system lock indefinitely, silently stalling all future builds** — this happened repeatedly (SwiftPM `.build` flock). Kill the ROOT wrapper process (not workers) to release cleanly; prefer lighter/filtered test lanes over one giant monolithic run for exactly this reason. — UNIVERSAL · carry-forward: PORT
- **A prior `sudo`/root-context build/test run poisons a shared build cache with root-owned files**, breaking the next unprivileged build with EPERM — this happened repeatedly across many sessions on the same project and was eventually made self-healing (auto-chown as part of the build script) rather than a manual recipe. Lesson: when a privileged bridge WRITES to a shared cache, chown before returning control to the unprivileged path, every cycle, not once. — UNIVERSAL (any dev environment mixing sudo/non-sudo CI paths) · carry-forward: PORT
- **A silently-empty test run ("0 tests executed") reads exactly like a pass** in output — always assert on the actual test COUNT, not just exit code / "passed" text. — UNIVERSAL · carry-forward: PORT
- **A gated/self-skipping test suite that is never wired into ANY CI lane's filter list runs NOWHERE, and its "green" history is meaningless** — a real regression shipped and nothing caught it for days because the guard suite existed but wasn't in the invocation list. Wiring a gated suite into its lane's filter IS part of landing the feature it guards, not an afterthought. — UNIVERSAL · carry-forward: PORT

## Theme: Test-writing discipline (dishonest tests, false greens, teeth)

- **SwiftUI "dishonest test" pattern:** ~15 tests asserting tautologies (set a closure, call it, assert it was called) gave false-green confidence — worse than no test. Litmus test for any assertion: "what production behavior breaks if I delete this line of source? If the answer is 'nothing the test could detect,' restate or delete." — UNIVERSAL (single best one-liner in the whole file for test-quality review) · carry-forward: PORT
- **"ALWAYS demonstrate teeth on a real-UI/regression test"** — a green that has never been shown to go red is not a guard. Revert the fix, rebuild, confirm red, then restore. Codified as a repeatable "negative control" switch pattern (env-var-gated deliberate break + a helper checked for that specific name) rather than hand-reverting each time. — UNIVERSAL (this is a core testing methodology worth carrying whole) · carry-forward: PORT
- **Teeth mutations must not flow through the SAME helper they're meant to pin (self-referential false green)** — if the expected side of an assertion is computed via the same code path being tested, a shared bug moves both sides together and the mutation stays green. The expected side needs an INDEPENDENT oracle (a different std API, or hardcoded literals). — UNIVERSAL · carry-forward: PORT
- **A regression guard that CRASHES instead of FAILING (force-unwrap in a test) wedges the whole test lane** — a crashed xctest worker can hang forever holding shared locks. Assertion paths in tests must use safe-unwrap/guard-fail, never force-unwrap. — UNIVERSAL · carry-forward: PORT
- **A "surviving mutation" is not automatically a weak test — verify the mutation actually breaks real behavior before "fixing" the test.** One case: an API silently URL-sniffed a plain string, so a "degraded" test mutant was actually behavior-preserving and the original green was honest. Probe runtime behavior empirically before strengthening either side. Companion: confirm a mutant actually COMPILED (grep the build log) before trusting a teeth run's verdict — same-second incremental rebuilds can silently reuse the old binary. — UNIVERSAL · carry-forward: PORT
- **A global mutable-state test sink (a process-global event collector) gets polluted by unrelated PARALLEL test suites emitting into the same sink** — an exact-match assertion on it flakes under `--parallel` even with a mutex serializing the sink's OWN tests against each other, because unrelated suites aren't excluded. Fix: filter the assertion to the test's own marker/span-name; don't assume a global is exclusively yours. — UNIVERSAL (any test suite with shared global observability state) · carry-forward: PORT
- **A "leak" claim in a lifecycle test must first check whether retention is BOUNDED (a capped cache) vs unbounded** — a teardown-count assertion became a false-positive "leak detector" when a later perf optimization changed the lifecycle from hard-teardown to park-in-a-bounded-cache; the test needed rewriting to assert the NEW correct behavior, not "more robustly" re-assert the old one. Diagnose-before-fixing means reading the actual current code path, not hardening a stale expectation. — UNIVERSAL · carry-forward: PORT
- **Before building a new invariant/guard test, grep `Tests/` for an existing one** — a bundle-cap doc-drift guard was built from scratch duplicating (and weaker than) an existing one whose existence was even named in a progress log the author had read but not registered. State-check the TEST surface the same way you'd state-check a feature before building it. — UNIVERSAL · carry-forward: PORT
- **Serial-suite per-test timing is NOT comparable to targeted/isolated per-test timing** — a false 150× perf-win claim was made by comparing a test's time in a full serial run (~5s, inflated by serial-context artifacts) against its time run alone (0.014s). A perf claim must use the SAME run mode for before/after. — UNIVERSAL (perf-measurement discipline) · carry-forward: PORT
- **`--parallel --xunit-output` per-test times are CONTENTION wall-clocks under load, not execution time** — a trivial no-IO test reported the same multi-second time as a heavy test under parallel contention. For true per-class profiling use a SERIAL run and parse log text (xunit output requires `--parallel`, so serial has no XML — text log is the only source). — TOOLING/HARNESS · carry-forward: DISTILL
- **Tests can silently write to the developer's REAL application-support state** if a model's default init falls back to production directories (`defaultDirectory()`/`defaultStoreURL()`) — confirmed real `history.json`/`LocalHistory` polluted with test markers and 132MB of test bloat. Fix: redirect default-dir helpers to a tmp dir under the test-runner's own env-var signal (e.g. `XCTestConfigurationFilePath`), covering ALL default-init call sites, not just the ones a prior partial fix touched. — UNIVERSAL (test hermeticity — this is a serious, easy-to-miss class) · carry-forward: PORT

## Theme: Board/tracker hygiene (tasked MCP specifics)

- **Board `TSK-NNN` ids are a totally different numbering space from the built-in TaskList's `#NNN`** and they collide numerically — this produced 3+ real cases of a board ticket being validated/closed against work done for the UNRELATED same-numbered TaskList item. Defense: before validating any `fixed` ticket, compare its recorded understanding/triage/fixed reasons against the board's own title+report; a topic mismatch = bounce to progress with a correction note, never validate. — PROJECT-SPECIFIC (tooling identity) but the underlying discipline (verify the ticket you're closing is the ticket that was worked) is UNIVERSAL · carry-forward: DISTILL
- **The board is shared across projects/agents** — grep the repo before acting on any board task id to confirm it belongs to this project. — PROJECT-SPECIFIC · carry-forward: SKIP (tool-specific)
- **`task_restate` (reported→ack) is the (undocumented) mechanism to CLEAR an owner-park gate** — used to bulk-convert 61 wrongly-auto-parked items into agent-owned spikes. — PROJECT-SPECIFIC · carry-forward: SKIP

## Theme: Security patterns (from the audit)

- **Anchor temp-dir/containment prefix checks with a trailing-slash-aware compare, not `hasPrefix`.** `/var/folders/<rand>/T` has no trailing slash; a bare `path.hasPrefix(temp)` admits a sibling directory like `/var/folders/<rand>/T-attacker/`, escaping the jail. Always `== root || hasPrefix(root + "/")`. This exact flaw existed in TWO independent copies of a boundary check (drift between duplicated logic) — factor a shared `isContained(_:in:)`. — UNIVERSAL (classic path-jail bug) · carry-forward: PORT
- **Check containment BEFORE existence** — throwing "not found" before "permission denied" leaks an existence oracle for out-of-jail paths. — UNIVERSAL · carry-forward: PORT
- **Binding to 127.0.0.1 does NOT make a local HTTP server safe** — DNS rebinding lets an attacker's page in the user's browser get same-origin requests to it. A loopback file-browser/server needs a Host-header allowlist, GET-only (or CSRF protection), and a real canonicalize+`starts_with(root)` path jail on every served path. A shipped web-tier server was missing all three → arbitrary file read. — UNIVERSAL (any local dev server / MicroApp-hosting design in the greenfield project) · carry-forward: PORT (directly relevant to the "agent-centric, non-blackboxy" web-facing surfaces planned for the next project)
- **`RLIMIT_AS`/`RLIMIT_DATA` are accepted but NOT enforced on macOS** — a memory-cap subprocess resource limit is security theater there; what IS enforced: `RLIMIT_CPU`, `RLIMIT_FSIZE`, `RLIMIT_NOFILE`. For a true RSS bound, need `sandbox-exec` or a private jetsam API. — PROJECT-SPECIFIC (macOS platform fact) · carry-forward: DISTILL
- **Redaction must sit in front of EVERY surfacing/consuming path, not just the obvious detail view** — a search/snippet feature bypassed a manual-redaction detail view and would have leaked raw sensitive content; fix was a shared `redactedEvents(from:)` entry point that all consumers route through. — UNIVERSAL · carry-forward: PORT

## Theme: Diagnosis methodology (transferable habits, not bug-specific)

- **For any "is the underlying data-model actually correct?" vs "is the render broken?" question, verify the parse-tree/data structure directly (s-expression dump, etc.) before inferring from visual output.** Colors/pixels are 3+ layers downstream of the actual data and conflate independent failures. — UNIVERSAL · carry-forward: PORT
- **A "live-only" UI bug usually has a headless-testable data/wiring layer underneath — prove that layer first**, narrowing the truly-live surface to the genuine re-render mechanics rather than guessing at the whole bug. — UNIVERSAL · carry-forward: PORT
- **Self-describing failure traces (a `lastTrace` string on the harness action naming exactly which link in a multi-step chain broke) repeatedly resolved bugs in ONE run** that otherwise took many rounds of blind diagnosis — give every multi-link harness/action a trace channel up front. — UNIVERSAL (debugging-infrastructure investment) · carry-forward: PORT
- **A "blocked, awaiting owner approval" tracked item may already be DONE** — grep the code for the supposedly-missing implementation before re-pinging the owner; a real case had the item stale across multiple handoffs after the underlying feature actually landed weeks earlier. — UNIVERSAL · carry-forward: PORT
- **Root-cause discipline pays off across a whole class, not one instance** — "does the same pattern live elsewhere" catches sibling bugs (a scroll-reset bug and a footer-blank-on-switch bug turned out to be the SAME class: imperative state populated around a switch, raced by declarative render reading it).

## In-process UI-event synthesis — the closed constraint matrix (TSK-620, 8 numbered findings)

A long, carefully-earned investigation into whether SwiftUI controls can be clicked/interacted with purely in-process (no real OS event injection), landing on a definitive NO with 8 documented reasons: NSControl tracking loops need queue-posted events not direct sends; queued events don't route to un-ordered windows; a click on a non-key window gets swallowed as the activating click; SwiftUI controls inside NSHostingView aren't NSViews so accessibility-identifier/view-tree walks can't find them; the in-process accessibility tree is empty (SwiftUI only materializes AX elements for EXTERNAL AX clients, and TCC for the test runner is owner-only/SIP-blocked); WindowServer refuses key/activation to a root-uid app in a user GUI session; a fork/exec'd app can never self-activate post-macOS-14 (cooperative activation) — only a real LaunchServices `open` launch works; and synthesized NSEvents don't drive SwiftUI gestures even on a genuinely key+active window (SwiftUI's gesture pipeline needs real WindowServer-backed CGEvent input, which needs the owner's AX TCC grant). The sanctioned fallback that actually works: exercise the exact action closure the control is wired to, in the LIVE app, and assert the cross-process rendered outcome via a dump channel. — UNIVERSAL (this is possibly the single most valuable investigation to carry forward almost verbatim — it will save the next project from re-discovering all 8 of these constraints the hard way if any AX/UI-automation testing lane is planned) · carry-forward: PORT (as a design constraint document for any SwiftUI UI-testing infrastructure)

## Key learnings from this batch

1. **The Rust-core migration template (6-step FFI slice recipe + wire-vs-raw-bytes rule + sans-IO-core boundary + "one core N front-ends via a shared view-model") is the single most directly reusable architectural artifact in this whole batch** — it maps almost 1:1 onto the greenfield project's stated goal of a Rust core supporting WebUI/TUI/remote transport.
2. **A recurring, expensive class of bug across this whole project: build/link-system staleness silently serving stale artifacts as if they were fresh** (SwiftPM not tracking a static-lib input, "0 tests executed" reading as a pass, tailed/piped output hiding a gate failure, a build reporting "Finished 0.13s" that didn't actually recompile). Any greenfield CI/build design should treat "prove the artifact under test is actually fresh" as a first-class, automated concern, not a manual habit.
3. **Multi-agent/workflow orchestration produced a long, hard-won process playbook** (worktree commit discipline, file-disjoint verification, gate-the-committed-commit-not-the-torn-tree, bundle-before-cleanup, ahead=N as the real merge signal) that should be adopted as standing operating procedure from day one of the greenfield project rather than relearned.
4. **The SwiftUI+AppKit/WebKit hybrid-view compositing class (representable occlusion, ImageRenderer false-green, hidden() vs opacity() for retained WebViews) cost 4+ wrong-fix rounds each time it appeared** and is a durable architectural hazard for any similar hybrid UI stack — worth a design doc up front rather than rediscovery.
5. **The in-process UI-event-synthesis investigation (TSK-620) definitively closes off an entire testing strategy (in-process SwiftUI click synthesis) that a new project might otherwise spend real time attempting** — carry the conclusion, not just the war story.
6. **Test-quality discipline items (dishonest-test litmus test, teeth-demonstration requirement, self-referential-oracle trap, global-state test pollution) form a coherent testing philosophy** independent of this specific codebase and are worth adopting as house style.

## Decision records found — decision + rationale + outcome

- **Decision: default-OFF capability gate + Swift fallback for every Rust-core migration slice, never delete the Swift path until soaked ON.** Rationale: de-risk a large incremental native-code migration. Outcome: held up across the whole migration; caught real Rust-side bugs via differential fuzzing without ever blocking shipping.
- **Decision: `default-members = ["crates/core","crates/ffi"]` keeps TUI/web front-end bins out of the merge gate and the macOS app's exec-size budget.** Rationale: avoid bloating the shipped Swift app with unrelated front-end deps. Outcome: worked as designed; front-ends build only via explicit `cargo run -p`.
- **Decision (owner, 2026-06-06): NO UI tests on the Mac host — UTM VM only.** Rationale: the host is the owner's actual working machine; spawned test windows disrupt work. Outcome: drove significant VM test-infrastructure investment (ulimit fixes, GUI-session bridging, screen-capture TCC workarounds) but was honored throughout; became `MDV_RUN_SMOKE_GATE=1` opt-in rather than default for the pre-install smoke.
- **Decision: `killall <exec-name>` banned everywhere in scripts/tests, replaced with env-marker-tagged process reaping.** Rationale: the shipping app and every test-spawned instance share an executable name, so a blanket killall repeatedly killed the owner's real running app (recurring, multi-site incident). Outcome: fixed at the `AppLauncher` site, then found again at `install-app.sh` (a second site) weeks later — the fix pattern is right but required re-discovery per call site; a lint/grep sweep for `killall` would have caught it sooner.
- **Decision: iCloud-synced `~/Documents` repo location was abandoned after a sync incident emptied the tree; canonical repo relocated, with an explicit "never re-enable Desktop&Documents sync without relocating first" guard.** Rationale: iCloud file-provider re-stamping caused intermittent codesign failures AND ultimately destroyed working-tree data. Outcome: durable — repo now lives outside any synced folder; the mitigation for the codesign-only symptom (build/sign in a non-synced TMPDIR) was kept as defense-in-depth even after relocation.
- **Decision: agent self-validation permitted for pure-logic/model/FFI behavior with an automated-test artifact, but NOT for WebView/AppKit-rendered visual behavior without a VM-run render test.** Rationale: host-green is not proof of on-screen correctness for hybrid UI. Outcome: this bar was clarified/tightened repeatedly across sessions (moving from "leave render at review for the owner" to "the VM is up, agent must build+validate render too") — the boundary of what counts as sufficient evidence kept moving as VM tooling matured.
