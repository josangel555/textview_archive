## Learnings for the rebuild

1. **Pixel-test infrastructure from day one, not retrofit:** TSK-488 rework arc took 9 commits partly because pixel-regression guards didn't exist initially. The rebuild should ship T5 PixelTestCase harness + ui-snapshot.sh *before* building major UI. Real pixels catch compositor/z-order/visibility bugs that ImageRenderer and headless walks miss. Codify the false-green trap (ImageRenderer = LIE for representable-occlusion) into team knowledge upfront.

2. **Security coverage is a first-class lane, not an afterthought:** This slice systematized coverage for parsing functions (scheme allowlist, slug dedup, aggregation). Future rebuild should allocate a dedicated security-audit sprint (6-8 weeks) targeting the same functions *before* shipping: link/image-scheme validation, HTML entity escaping, JSON depth caps, CSV injection patterns. Build tests as you discover risks, not retroactively.

3. **VM test harness is critical path, not optional:** TSK-492 investments (Aqua LaunchAgent, ui-snapshot.sh, AX reader, MDV_UI_SCENE control) were essential to catching visual regressions (tab strip, file-change dot, line-hover highlight). Plan 2-3 weeks of harness-building *during* early UI work. The rebuild should have Aqua/pixel-lane operational by week 3-4, not bolted on at week 6.

4. **Document rework-arc decisions in commit messages:** When a feature requires 7+ commits across multiple sub-phases (core → wiring → validation), say so explicitly in the subject or follow-up docs-commit. The rebuild should establish a convention: `[EPIC: xyz/N]` prefix for slice N of a multi-commit feature, with a final docs-commit summarizing the breakdown. Reduces reader confusion ("is this three bugs or one feature?").

5. **Refactor for test coverage, not elegance:** TSK-473 (xattr dedup) landed with round-trip unit tests *before* merging, making the extracted module immediately regression-guarded. Future: whenever consolidating duplicate code, write the test in the new module first, then retrofit both call-sites. This prevents the "refactor introduces a subtle bug" trap.

6. **Institutional knowledge capture (LESSONS) is non-optional:** This slice repeatedly codified hard-won insights (compositor occlusion, iCloud race, VM toolchain skew, killall footgun) into LESSONS.md and CLAUDE.md rules. The rebuild should reserve 1-2 commits per week for LESSONS updates *as issues are discovered*, not in a final retrospective. A team that forgets why the build script signs in TMPDIR will re-introduce the race. Treat LESSONS as versioned spec, not optional notes.
