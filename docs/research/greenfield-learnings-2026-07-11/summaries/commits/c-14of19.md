## Era Narrative

By late June, the project had **shipped ~66 user-facing features** (as recorded in the June 22 handoff); the remaining runway was consumed by **scaling two major Rust ports (Formula and Folds) from gated/tested to flipped-on-by-default**, accompanied by a parallel push to **harden test infrastructure and close the VM validation gap** that had silently undermined prior UAT claims.

The **Formula engine port** (TSK-1213) was the centerpiece of this era: 28 core Rust implementation commits (slices 1–3i), each handling a vertical slice of calculation logic (arithmetic core, cell refs + resolver, function calls + ranges, comparison ops, string literals, math functions, conditionals, lookups, date functions, FFI dispatch). Each slice was paired with **Swift↔Rust parity tests**, and as slices landed, differential fuzzing exposed **5 new Rust bugs** (coerce_cell whitespace handling, inf/nan textual forms, number formatting, TRUE/FALSE boolean recognition, MATCH/INDEX edge cases). Each bug was fixed + re-verified; the result was a formula engine that passed **end-to-end differential fuzzing across every eval path** — a durable "this won't regress" gate that required no human validation.

In parallel, a **test infrastructure campaign** (TSK-1130/1131/1134) codified lessons from prior false-negatives: the `MDV_ENABLE_BROKEN_*` teeth-switch pattern, Swift Testing hybrid pilot, coverage scripts with manual-merge fallbacks, and a **UAT harness bring-up** that fixed three silent failure modes (root-poisoned .build causing 0-XCTest runs, viaOpen launch env non-delivery, coverage script profraw-merge ARG_MAX overflow). Each harness fix was captured in LESSONS.md for future reference.

By early July, the **folds port** (TSK-1202) completed behind its gate with **6-language A/B parity proof**, and highlights fixes (TSK-1201) swept comment/SCREAMING_CASE recognition across C-family and block-comment languages. The **security-fuzz roadmap** (3 audit targets: highlight/web/wire, + markdown XSS) shipped 100% complete.

The era closed with **owner-gated decisions pending** on formula + folds display (whether to flip them on), but the technical bar for "ship-ready" had been set: gated + parity-proven + fuzz-hardened + UAT-framework-confirmed.

**parity-prove + fuzz-validate before claiming "done"** meant the port shipped with 
production-grade confidence, not "seems to work" handwaving.

## Learnings for the Rebuild

1. **Differential fuzzing as production insurance, not testing luxury**: The formula port 
   proves that parity-fuzzing across a Swift-vs-Rust port is a **load-bearing requirement**, 
   not a "nice to have". The 5 parity-found bugs would have shipped as silent logic errors 
   without the fuzz tests. Rebuild: **dedicate 20–30% of porting effort to parity fuzzes**; 
   don't defer them to post-ship validation.

2. **Early VM harness validation catches silent failures at scale**: The 0-XCTest false 
   negative, viaOpen env non-delivery, and coverage-script ARG_MAX overflow were all 
   **silently undermining UAT confidence until they were diagnosed in late June**. Rebuild: 
   **bring up the full VM test/build/harness lane by end of week 1**, not as a 
   late-stage luxury. The earlier harness validation happens, the fewer stale false 
   negatives accumulate.

3. **Spike + decision records are durable architecture artifacts**: The formula spike 
   (4e2ead02, a9870c51) + consolidated migration roadmap (67205386) + progress logs 
   (c80b204a, d1a2e995) created a **permanent audit trail of why each decision was made**. 
   When the rebuild faces similar "build vs adopt, Rust vs Swift, when to ship vs defer" 
   questions, these spikes become reference material. Rebuild: **record spikes as first 
   commits, embed decision rationale in commit messages**; don't lose this institutional 
   memory.

4. **Slice major ports vertically, not horizontally**: The formula port's 28-commit slice 
   approach (arithmetic core, cell refs, functions, FFI, recalc) meant **each commit was 
   independently testable and landable**. A 2000-line monolithic commit would have been 
   harder to review, harder to debug, harder to land cleanly. Rebuild: **default to 
   vertical slicing (a feature slice from input to output) over horizontal layering 
   (all UI, then all logic)**.

5. **Teeth-proofs are non-negotiable for CI/harness changes**: The three VM harness fixes 
   (root-owned .build, open --env non-delivery, profdata merge fallback) each required 
   **immediate defensive guards or fallback logic**, because silent failures had already 
   happened. Rebuild: **don't ship a harness fix without a test that proves the old path 
   was failing** — the guard's job is to prevent regression, and that requires teeth.

6. **Documentation velocity tracks feature delivery**: The 35.9% docs-to-code ratio in this 
   slice (vs. typical 10–15%) is not overhead; it's a signal that **decision-making and 
   knowledge capture were keeping pace with implementation**. Rebuild: **if docs-to-code 
   ratio drops below 15%, ask why — usually it means decisions are being made silently**, 
   or knowledge capture is lagging. The high ratio here meant the project was **self-aware 
   of its own progress state** at every checkpoint.
