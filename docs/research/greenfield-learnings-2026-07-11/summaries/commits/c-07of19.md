## Learnings for the Rebuild

1. **Measurement MUST come before perf diagnosis.** TSK-267/592/598/619 showed that EVERY perf claim required vm-profile.sh output or signpost traces. The rebuild should **BUILD the harness first** (vm-profile.sh, xctrace integration) before any perf work; this slice's "14 commits to discover 400ms TreeSitter stall" would have been "1 commit + 1 trace" if harness existed earlier.

2. **Doc logging is load-bearing infrastructure, not optional.** The "docs: log +N" pattern + AUTONOMOUS_PROGRESS.md distillation is HOW the project reconstructs mid-session state. Post-compaction, the handoff must include a log pointer. The rebuild's docs pipeline (which items landed, which tests guard them) must be wired from day 1, not retrofitted.

3. **Exact-closure UAT (real-event cross-process harness) = hard prereq for session/git/editor features.** This slice discovered in-process synthesis is impossible; the rebuild should **start with exact-closure VM harness design** (not host-only headless tests for feature-landing claims). TSK-313/314/522/523 validation only became trustworthy AFTER TSK-620 harness work; features built before the harness had to be re-validated.

4. **Root-cause discipline + measurement > patch-around speed.** The 9c8b9a5a revert (finite container 17x worse, replaced with textContainerOrigin override) took 1 day but locked in the RIGHT mechanism. A "just make it fast" patch-around approach would have built perf debt; measurement forced correctness. Rebuild should **institutionalize "measure first" as a gate** (no perf claim without a trace), and revert-if-wrong should be the team's first reflex, not a last resort.

5. **Security findings require deterministic regression guards, not manual audits.** TSK-549 (git config injection) included a test (git_status_never_executes_repo_local_fsmonitor_command) that FAILS with the override removed — proving teeth. The rebuild should **fuzz + test every threat model** (hostile repo, large files, untrusted input) from the start, not retrofit guards after an audit surfaces issues.

6. **Harness evolution is a multi-day upfront investment, not a follow-on task.** TSK-620 (ui-click → exact-closure) took 9 commits / 2 days and STILL discovered new constraints (8 synthesis rules to LESSONS). The rebuild should **allocate 1 week for harness design + proof-of-concept** BEFORE feature work; this slice's "fixes need VM validation" bottleneck only dissolved once the harness was LIVE and running 40+ tests/day.
