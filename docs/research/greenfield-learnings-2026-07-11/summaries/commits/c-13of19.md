## Learnings for the Rebuild

1. **Bundled docs = fewer sync taxes.** Pairing every feature commit with its changelog entry prevents "someone needs to go back and catalog what shipped" friction. The rebuild should adopt this as standard practice, not optional.

2. **Epic slicing wins for large features.** The image editor's 46 features shipped in ~35 commits (1.3 commits per feature). This is healthy—features are small enough to land incrementally, large enough to carry real value. Avoid both extremes: tiny "add one button" micro-tickets and monolithic "build the entire editor" macros.

3. **Rework should be instrumented.** LocalHistory rework (TSK-1103) was necessary (memory bug) but came *after* shipping. A rebuild should front-load complexity-spike analysis: identify high-risk subsystems (versioning, history, merge) and spike/design first, then build-out-slice pattern.

4. **Warm caching + batching is multiplier perf.** Session-switch perf (TSK-1040–1044) wasn't fixed by a single change; the wins came from:
   - Warm WebView cache (avoid rebuild)
   - Batched reactive updates (coalesce many re-renders)
   - Scroll preservation model (independent of UI render)
   
   A rebuild should **design for caching and batching upfront** (e.g., session model stores scroll/cache keys in one snapshot, restore reads from it), not bolt these on as fixes.

5. **Handoff discipline pays off.** Four explicit handoff checkpoints (every ~50 commits) let the owner course-correct mid-sprint. They also survive context-compaction—when tokens reset, `HANDOFF.md` tells the next session exactly what was accomplished. Rebuild should encode checkpoints as a **gates, not extras**.

6. **Data-loss prevention needs integration testing.** The no-clobber save + LocalHistory + snapshot-on-save stack (TSK-768/1103) involves coordination between:
   - Save guard (detect external changes)
   - Conflict decision (user chooses merge/overwrite)
   - Snapshot recovery (undo data loss)
   
   These shipped as separate commits (healthy slicing), but integration testing came *after*. Rebuild should treat save/conflict/recovery as a **single acceptance criterion**, not three independent features.
