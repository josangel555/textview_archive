## 3. How to drive the board over HTTP (curl + jq)
```bash
EP=http://localhost:8787/mcp
rpc(){ jq -cn --arg n "$1" --argjson a "$2" '{jsonrpc:"2.0",id:1,method:"tools/call",params:{name:$n,arguments:$a}}'; }
call(){ printf '%s' "$1" | curl -s -m12 -XPOST "$EP" -H 'content-type: application/json' -H 'accept: application/json' --data-binary @-; }
# list (result is JSON wrapped in result.content[0].text — double-decode):
call "$(rpc task_list '{}')" | jq -r '.result.content[0].text' | jq -r '.tasks[] | [.id,.state,.title] | @tsv'
# create: {title, report, agent}  (+ optional type; project param is IGNORED)
# comment (always works, any state): task_comment {id, agent, body}
# advance one lane: task_restate {id,agent,understanding} → task_triage {id,agent,note} → task_claim {id,agent} → task_record {id,agent,summary,to:"fixed"}
```
- `task_record` `to` ∈ {fixed, review, progress} but agents are refused `review` — use `fixed`.
- No `task_create_many` yet (owner was building it; not deployed at handoff). Loop `task_create`
  with a `sleep 0.12` between calls (avoids the lock/lease race, GAPS#4).
- Helper `/tmp/tk.sh <tool> '<json>'` exists (deno-based) but direct curl is more reliable.

## 4. Hard-won lessons this session (full text in `LESSONS.md`)
- **Workflow fix-fleet "applied" ≠ gate-green.** Agents edit per-file and self-report success,
  but the central gate caught REAL defects every time: the audit-fix wave had 6 (incl. a UTF-8
  scalar-split in `visible_text` truncation that overshot the byte cap + emitted U+FFFD); W1
  surfaced clippy-1.92 drift. **Always: agents edit-only (file-partitioned or worktree-isolated),
  THEN a central gate, THEN land. Never land on self-reports.**
- **Read the real gate exit, not the wrapper.** `bash gate.sh > log; echo "X=$?"` — the
  background-task "exit code 0" notification is the trailing `echo`, not the gate. Grep the
  `^X=` marker (or the test summary) from the log.
- **clippy 1.92 drift:** `rust-core-gate.sh` (clippy `--all-targets` with `expect_used`/`panic`
  denies) went red on clean `main` after a toolchain bump — hit `ffi/build.rs` (2× `expect` on
  cargo-guaranteed env vars) + 2 deliberate test panics. Fixed in W1 (build.rs warn+return; test
  `#[allow(clippy::panic)]`). If the gate is red, check this first.
- **Two file-mutating workflows collide** — isolate each in its own `git worktree` off `main`
  (W1 used the main tree, paper-cuts + perf used worktrees). Reap worktrees after landing
  (`git worktree remove --force` → `prune`); a stale build dir can block `rm` — retry.
- **Land via `git branch -f main <branch>` when the main tree is occupied** by a running
  workflow on another branch (can't `git switch main`); it's a true ff since branches sit on `main`.
