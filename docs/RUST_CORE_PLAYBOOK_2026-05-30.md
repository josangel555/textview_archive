# TextView Rust Core — Project Playbook

A tailored, production-grade Rust playbook for the headless TextView core: edition 2024 + MSRV 1.85, a flat cargo workspace splitting `forbid(unsafe_code)` core from quarantined FFI/unsafe edges, a deliberately tiny dependency set, and a sans-IO synchronous functional core that contains async/threading behind channel walls at the I/O boundary.

**Verdict:** Your instincts are right and the evidence backs them — a sync, sans-IO functional core (`&mut self` state machine, time/randomness injected, effects returned as data) is the single highest-leverage decision, and it's exactly what every reference project (quinn-proto, Crux, Firezone) and the xi-editor post-mortem converge on. The honest tension is concentrated in three places: (1) **mmap vs `forbid(unsafe_code)`** — they're literally incompatible, so default to safe `seek`+buffered reads and only quarantine mmap into a leaf crate if profiling demands it; (2) **LSP JSON-RPC multiplexing** — the only subsystem where async is genuinely idiomatic, so contain it behind a worker-thread + channel boundary rather than coloring the core; (3) **the wire format** — bincode is now unmaintained (RUSTSEC-2025-0141), so use `postcard` for the Rust-to-Rust internal/disk tier and `rmp-serde` (MessagePack) for the cross-language Swift/JS tier, since postcard/rkyv are Rust-only by design. Everything else is conventional 2026 Rust hygiene. Start dependency-empty and treat every `cargo add` as a reviewable event.

## 1. Rust baseline to adopt

| Decision | Choice | Why |
|---|---|---|
| **Edition** | `2024` | Current idiomatic baseline. Gives you fixed `if let` drop scopes (matters for your lock-heavy sync core), mandatory `unsafe extern`/`#[unsafe(no_mangle)]` (hardens FFI for free), and `resolver = "3"` per-target feature isolation. |
| **MSRV (`rust-version`)** | `1.85` | Hard floor: edition 2024 + let-chains require ≥1.85. Don't track latest; pick a deliberate floor and bump only with cause. `OnceLock`/`LazyLock` (≥1.80) and `core::range` (1.96) are available below/at this floor. |
| **Pinned toolchain** | `rust-toolchain.toml` (channel + components + targets) | Reproducible builds across all front-ends and CI. **Distinct from MSRV** — pinned toolchain answers "what builds it", `rust-version` answers "what's the contract". Pin both. |
| **Lockfile** | Commit `Cargo.lock` | You ship binaries/cdylibs/staticlibs — every consumer is an "application". Pin AND patrol (Dependabot/Renovate) so the lock doesn't rot into known-CVE territory. |
| **Latest stable (ref)** | 1.96.0 (2026-05-28) | Track Cargo updates: 1.96 patched CVE-2026-5223 (symlink extraction) / CVE-2026-5222 (URL-auth). |

**Non-obvious gotchas a Swift-fluent newcomer will trip on:**
- **Edition ≠ compiler version.** `edition = "2024"` is per-crate and orthogonal to which `rustc` you run. You can depend on any-edition crates freely.
- **RPIT lifetime capture flipped in 2024.** `-> impl Trait` now captures *all* in-scope generics by default. Use `+ use<'a, T>` precise-capturing to narrow when a returned iterator borrows more than you intended. Silent behavioral change.
- **`gen` blocks are still nightly.** The `gen` keyword is reserved but generators are unstabilized — implement level-triggered subscription iterators as plain `Iterator` impls or channel drains, not `gen { yield }`.
- **MSRV-aware resolver is default-on for 2024 crates.** `cargo update` may not pull the newest dep version; a "latest deps" CI job needs `CARGO_RESOLVER_INCOMPATIBLE_RUST_VERSIONS=allow`.
- **`std::env::set_var` is now `unsafe fn`.** It mutates process-global state. Launch git/jq/LSP with per-child `Command::env`/`envs`, never `set_var`.

## 2. Project layout

Single virtual workspace, flat `crates/` layout (matklad / rust-analyzer convention — `ls crates/` is the project map; flat doesn't deteriorate the way nested trees do).

```
textview/                      # repo root: [workspace] only, NO [package]
  Cargo.toml                   # workspace.members/.dependencies/.lints, resolver="3"
  Cargo.lock                   # the one lockfile
  rust-toolchain.toml          # pinned channel + components + targets
  rustfmt.toml  clippy.toml  deny.toml
  crates/
    textview-core/             # rlib · #![forbid(unsafe_code)] · the sans-IO functional core
    textview-proto/            # rlib · wire types + serde derives (postcard/rmp-serde)
    textview-ffi/              # staticlib+cdylib+rlib · Swift C-ABI shim · UNSAFE LIVES HERE
    textview-mmap/             # rlib · (optional) quarantined mmap zero-copy island
    textview-tui/              # bin · ratatui front-end (sync driver)
    textview-wasm/             # cdylib+rlib · wasm-bindgen front-end · NOT in default-members
    textview-remote/           # rlib/bin · WebSocket transport (the async island)
    xtask/                     # bin · build/bundle/sign/size-check automation
```

| Crate | Owns | Crate-type | unsafe posture |
|---|---|---|---|
| `textview-core` | State machine, rope/buffer/index, parsing orchestration, search, diff, session logic, subscription engine. Zero runtime deps. | `rlib` | `forbid(unsafe_code)` |
| `textview-proto` | Plain domain wire types + `#[derive(Serialize,Deserialize)]`. Keeps serde out of core's public types (avoids xi's serde bloat). | `rlib` | `forbid(unsafe_code)` |
| `textview-ffi` | `extern "C"` surface, `catch_unwind` shims, `#[repr(C)]` structs, cbindgen header. The ONLY place `unsafe` + symbol exports live. | `staticlib`,`cdylib`,`rlib` | `deny(unsafe_op_in_unsafe_fn)` + `// SAFETY:` per block |
| `textview-mmap` | (Defer) audited mmap island if profiling needs random-access GB reads. | `rlib` | quarantined unsafe |
| `textview-tui` | ratatui UI, arg parsing, sync drain-poll-feed loop. Dumb shell. | `bin` | `forbid` |
| `textview-wasm` | wasm-bindgen glue, browser tick driver. | `cdylib`,`rlib` | (generated glue) |
| `textview-remote` | WebSocket framing (tungstenite), the contained async edge. | `rlib`/`bin` | `forbid` |
| `xtask` | Cross-platform, type-checked build automation (`version="0.0.0"`, `publish=false`). | `bin` | `forbid` |

**Gotchas:**
- **wasm crate must stay out of `[workspace.default-members]`** — a plain root `cargo build` otherwise tries to compile the `cdylib` for the host (duplicate-lang-item errors). Build it only via `cargo build -p textview-wasm --target wasm32-unknown-unknown`. There's no built-in "this crate only builds for target X" switch (cargo #9650/#12274 still open).
- **`[profile.*]` and `resolver` are root-only.** Setting them in a member's `Cargo.toml` is silently ignored.
- **`cdylib`/`staticlib` crates need `rlib` alongside** or `cargo test` and Rust-side consumers (the TUI) can't link them.
- **Feature unification is global.** If `textview-tui` enables core's `git` feature and `textview-cli` doesn't, a build including both compiles core *with* `git`. You can't get a "lite" core just by not asking. Design features additively; use `dep:` syntax (`git = ["dep:git2"]`) to avoid leaked implicit feature names.
- **Dependencies point INWARD.** Orchestration depends on data structures, never the reverse — xi's literal reuse failure was welding edit logic to `Editor`/`View` so `xi-rope` couldn't be reused standalone.

## 4. Architecture

The three patterns you cite are the same shape under three names; adopt all three deliberately.

```
            ┌─────────────────────────── IMPERATIVE SHELL (per front-end) ──────────────────────────┐
            │  TUI loop │ Swift FFI driver │ WASM rAF tick │ WebSocket async driver │ worker pool    │
            │     │            │                  │                 │                      │          │
   real I/O │  files, sockets, subprocess stdio, CLOCK, RNG  ── all nondeterminism lives HERE         │
            │     │            │                  │                 │                      │          │
            │     ▼  feed input          drain effects ▲           ▲ inject now/seed                  │
            └─────┼───────────────────────────────────┼───────────┼──────────────────────────────────┘
                  │   (native calls in-process · serialized wire when remote)
            ┌─────▼─────────────────────────────────── FUNCTIONAL CORE (textview-core) ──────────────┐
            │  pure, SYNCHRONOUS &mut self state machine · #![forbid(unsafe_code)] · zero runtime deps │
            │                                                                                          │
            │  fn handle_input(&mut self, msg: Input)                                                  │
            │  fn handle_timeout(&mut self, now: Instant)        ← time is a PARAMETER, never read     │
            │  fn poll_effect(&mut self) -> Option<Effect>       ← side-effects returned as DATA       │
            │  fn poll_timeout(&self) -> Option<Instant>         ← tells the driver when to wake       │
            │  fn subscription_snapshot(&self) -> StateView      ← LEVEL-triggered: current state      │
            └──────────────────────────────────────────────────────────────────────────────────────────┘
```

**The sans-IO quartet generalizes beyond networking** (quinn-proto, Firezone): feed input → drain pending effects → tell me when to wake. It fits file-watch events, search progress, LSP responses, and your level-triggered subscriptions identically.

**Effects as data, not callbacks** (Crux's `Command<Effect, Event>`). The core *returns* an effect; the shell executes it and feeds the result back as a new event. This is what lets the same effect run locally (in-process) or ship over the wire (remote) with zero core changes. Swatinem's warning: the out-param/callback style is "infectious — you have to thread it through all the functions."

**Containing async/threading without coloring the core:**

| Edge | Containment strategy |
|---|---|
| File watching | `notify` spawns its own thread, delivers via channel → feeds subscription system. Core stays sync. |
| File read/write/fsync | Blocking std syscalls on the worker pool. This is where sync-first is on its strongest ground. |
| git / jq (batch) | One reader + one writer thread per child, channels into core. Route **a**: fully sync, zero async deps. |
| LSP JSON-RPC (concurrent multiplexed) | **The one honest conflict.** Either (a) hand-roll sync framing with reader/writer threads + a request-id→oneshot map, or (b) a single tokio runtime on a dedicated I/O thread, exposed to the core *only* via channels. Decide with a spike, not upfront. Run results to the core as **events** — don't drag the LSP protocol into the pure core. |
| WebSocket / browser remote | Async is pragmatic here; lives in `textview-remote` behind the same channel wall. WASM is single-threaded — abstract the thread pool behind a trait so the WASM build stubs it. |

**Level-triggered is validated** (Kubernetes reconciliation model): resend current state, client reconciles. Edge-triggered deltas silently and *unrecoverably* desync on a dropped/reconnected SSH or browser link. Test by asserting on the **coalesced snapshot** after N mutations, not on notification counts.

**Ports as traits, prefer static dispatch.** Generics+bounds for hot single-impl ports (zero-cost inlining); `Box<dyn Trait>` only for genuinely heterogeneous/swappable sets (e.g. a `StorageBackend` with mmap/in-memory/remote impls). The most-cited Rust hexagonal guide uses *async* ports — that's a web-server artifact, not a requirement; sync ports work identically.

**Honest pushback:** sans-IO is "a bit painful" for purely sequential request/response (your LSP/git/jq flows) and you *will* hand-write one drain-poll-feed loop per front-end. Mitigation: keep request/response subprocess protocols on worker threads surfacing only results, and centralize each front-end's drive loop in one auditable spot (a `poll_timeout` that doesn't advance = 100% CPU busy-loop; property-test that it strictly advances or returns `None`).

## 5. Per-domain gotchas + practices

**File I/O** (sync-first's strongest ground — std::fs is blocking by design)
- **Atomic durable save = all four steps:** temp-in-same-dir → `write_all` → `file.sync_data()` → `fs::rename` → **fsync the parent dir fd**. Skip the file fsync → zero-length file after crash. Skip the dir fsync → rename lost on reboot. Route ALL saves through one tested function.
- `tempfile::persist` preserves **nothing** — fresh temp file gets umask perms, no owner/timestamps/xattrs/ACLs. Read original metadata and reapply before rename.
- Temp file MUST be on the **same filesystem** as target (cross-device rename → `EXDEV` → non-atomic copy+delete).
- **Never** assume one `read()` fills the buffer or one `write()` drains it. Use `read_exact`/`read_to_end`/`write_all`. `read_exact` retries `Interrupted` but leaves buffer "unspecified" on `UnexpectedEof`.
- `File::create_new` (O_EXCL), never `exists()`-then-create (TOCTOU). `remove_dir_all` itself shipped a TOCTOU CVE — even std got this wrong.
- **mmap is the central no-unsafe tension:** every constructor is `unsafe` and external truncation → SIGBUS (uncatchable). **Default to safe `seek`+buffered reads** (BufReader at 64–256 KiB, not the 8 KiB default). Quarantine mmap into `textview-mmap` only if profiling proves random-access GB reads need it.
- **Paths are not UTF-8** (Unix = bytes, Windows = ill-formed UTF-16). `to_str()` returns `Option`; `to_string_lossy()` corrupts. Pick an explicit bytes-vs-lossy policy at the wire boundary.
- `BufRead::lines()` strips and collapses `\r\n`/`\n` — you lose line-ending style. Detect encoding + EOL once on open, store as document state, round-trip both on save.
- File watching is **not ground truth** — notify is "not 100% reliable" on Linux, drops events under large watch sets, emits nothing on NFS/SMB/proc/sys. Always re-stat/re-read on event; ship a `PollWatcher` fallback from day one.

**Networking / RPC / binary wire**
- **bincode is dead** (RUSTSEC-2025-0141). postcard (internal) + rmp-serde (cross-lang).
- **rmp-serde interop trap:** default `to_vec()` encodes structs as **arrays** (no field names); Swift/JS `Codable` expect **maps**. Use `to_vec_named()` for every cross-language message and document it.
- **Length-prefix every frame** (u32 LE length + body) when hand-rolling over TCP — a single `read()` returns partial or coalesced messages. The classic hand-rolled-protocol bug.
- **Hand-roll the RPC dispatch** (request-id-tagged framed protocol + your own match). tarpc/capnp-rpc force async (capnp-rpc's `RpcSystem` is `!Send`, pinning you to single-thread `LocalSet`); tonic drags tokio+hyper+HTTP-2. Study Cap'n Proto's capability/promise-pipelining model as a *reference*, but it has no Swift impl and only alpha Node-only JS.
- **Schema evolution is YOUR job** for non-self-describing formats — version the wire, gate changes. Graduate one boundary to FlatBuffers/prost only if manual discipline across 3 languages proves error-prone.
- **Three distinct error layers, do not conflate:** (1) internal per-subsystem matchable enums (`#[non_exhaustive]`, `Error+Send+Sync+'static`); (2) one versioned wire error `{code, message, data}` (JSON-RPC 2.0 model) — map internal errors *into* it, don't serialize the chain; (3) FFI integer code + last-error/out-param with `catch_unwind`.

**Async / threading**
- **`block_on` inside an async context deadlocks/panics.** The dedicated-runtime-thread bridge must run `block_on` on a non-runtime thread.
- **Never hold a std `Mutex`/`RwLock` guard across `.await`.** Pass ownership over channels instead of sharing.
- **std threads have NO cancellation** — you can't kill a thread blocked on a syscall. Design cooperative shutdown (a shutdown channel / `AtomicBool` at safe points) into long-lived workers from day one. This is the real ergonomic cost of sync-first vs async (where drop = cancel).
- **Function coloring is viral** and runtime coupling sneaks in transitively — one async lib drags tokio into the whole binary. Feature-gate async so it can't infect WASM/TUI builds.
- `std::sync::mpsc::Receiver` is single-consumer — you can't share it across a worker pool. MPMC needs `crossbeam-channel`.
- `async fn` in traits (stable 1.75) is static-dispatch only — no `dyn`. An RPC dispatcher on trait objects hits this; prefer enums/static dispatch.

**FFI / unsafe**
- **`forbid` > `deny`:** `forbid(unsafe_code)` can't be locally `#[allow]`-overridden. That's the point — and why the FFI/zero-copy edge must be a *separate crate* (you can't punch a hole in `forbid` within one crate).
- **Panic across `extern "C"` is UB.** `catch_unwind` at every entry point (or `panic=abort`, which makes it a hard kill). `catch_unwind` only catches *unwinding* panics — useless under `panic=abort`.
- `#[repr(C)]` on **every** type that crosses — default layout is unspecified; forgetting it is silent corruption, not a compile error.
- **Allocate and free on the same side.** Expose explicit `*_free()` C functions; never free in Swift what Rust allocated.
- Rust 2024: `unsafe fn` bodies are no longer implicit unsafe blocks (`unsafe_op_in_unsafe_fn`); `#[no_mangle]` → `#[unsafe(no_mangle)]`. Per-block `// SAFETY:` comments via clippy `undocumented_unsafe_blocks` + one op per block via `multiple_unsafe_ops_per_block`.
- **Miri validates the Rust side only** — it does not run your Swift/C. Green Miri proves the Rust half, not the cross-language contract. Test under both Stacked and Tree Borrows; treat a Stacked-Borrows failure as real even if Tree Borrows passes (neither is the finalized model).
- For pure byte↔struct reinterpretation use **`zerocopy`** (derive-checked, unsafe-free) over hand `transmute`.

**Performance**
- **Measure first.** `[profile.release] debug = "line-tables-only"` + `RUSTFLAGS="-C force-frame-pointers=yes -C symbol-mangling-version=v0"` or stacks are garbage.
- **Allocation discipline is the zero-dependency, highest-leverage GB-core win:** `Vec::with_capacity`/`reserve`, `clear()`/`clone_from` reuse, `Cow` at parse boundaries, `read_line` into a reused `String` (not `.lines()`), `write!` into a reused buffer (not `format!`, which heap-allocates every call — bites highlighting + serialization). Bake into the style guide.
- **Don't write SIMD.** `std::simd` is nightly indefinitely; `wide`/`pulp` carry internal unsafe. Lean on `memchr`/`regex` (audited SIMD behind a safe boundary).
- **`target-cpu=native` SIGILLs on older CPUs** — wrong for distributed binaries. Pick an explicit baseline (x86-64-v2/v3).
- Arenas (`bumpalo`) for per-parse scratch only after DHAT shows parse-time allocation is hot. Alternative allocators (jemalloc/mimalloc) only for the long-running Linux server tier, gated on a benchmark.

## 6. Testing strategy

Your sync, sans-IO core is the **easiest possible thing to test deterministically** — the DST literature's recommended pattern (Polar Signals' state-machine-with-`receive`/`tick`) is itself a sync design that bans async in the core. Alignment is not a coincidence.

**Pyramid (all built-in, zero deps):**
- Put ALL logic behind `lib.rs`; keep `main`/FFI shims thin — a binary-only crate can't be integration-tested, and `tests/` + doctests pressure-test your public API.
- Unit tests in `#[cfg(test)] mod tests { use super::* }` for private logic; `tests/<feature>.rs` for public behavior; doctests as compile-checked usage examples.
- Shared helpers in `tests/common/mod.rs` (subdir form) — `tests/common.rs` becomes a phantom "0 tests" crate.

**Determinism by construction:**
- Inject a `Clock` trait (`fn now(&self) -> Instant`) and a single seeded `rand_chacha` RNG. **Forbid `Instant::now()`/`SystemTime::now()`/`thread_rng()` in core modules** — enforce with a clippy `disallowed_methods` lint. One stray call destroys replayability. Skip `mock_instant`; the hand-rolled trait is the DI you need anyway.
- Never assert on `HashMap` iteration order (randomized per-process) — use `BTreeMap` or sort.
- Model the worker-pool/RPC/subscription engine as a state machine driven by a single-threaded message bus in tests. Test ordering = message-application order. No `thread::sleep`-based sync.

**The honest DST conflict:** mainstream writeups claim single-threaded DST *requires* async I/O. That applies to in-process simulated *distributed systems doing real network I/O*. Your model differs — real I/O lives in worker threads *outside* the simulated boundary, mocked behind traits. You get DST determinism without async contagion. Polar Signals' own pitfall: resist putting "just a little logic" in the threaded driver where DST can't see it.

| Layer | Tool | Targets |
|---|---|---|
| Property | `proptest` | wire encode↔decode round-trip, paging-offset math, edit/undo idempotence, `poll_timeout` strictly advances. Commit `proptest-regressions/`. |
| Snapshot | `insta` (or std-only golden file to start) | highlight token streams, RPC response shapes, **converged subscription state**. Commit `.snap`; insta auto-fails in CI. |
| Fuzz | `cargo-fuzz` + `arbitrary` | markdown/tree-sitter feed, the **binary wire decoder** (untrusted remote bytes), large-file paging. Derive `Arbitrary` on op-enums to fuzz operation *sequences*. Nightly + C++ toolchain. |
| Concurrency model | `loom`/`shuttle` | ONLY for hand-written lock-free/atomic primitives. **If you stay on std/crossbeam channels + Mutex driven by the message bus, you likely skip these entirely** — the right call under minimal-deps. |
| Coverage | `cargo-llvm-cov` | Region-level, works on macOS (tarpaulin's ptrace backend is Linux-x86_64 only). A signal, not a 100%-obsession. |
| Runner | `cargo-nextest` | Process-per-test isolation (critical for tests spawning git/jq/LSP or touching global state), retries, JUnit. |

`cargo test` runs tests in parallel threads — tests mutating env/temp-dirs/ports race. Use `tempfile` per test (never real user dirs) + nextest's process isolation. Inject subprocess spawning behind a trait so most tests use a scripted transcript, not a live process.

## 7. Build / packaging / distribution

**Profiles** (pure config — adopt now):
- `[profile.release]` stays default-ish for dev iteration.
- `[profile.dist] inherits="release"`: `lto="thin"`, `strip=true`, `trim-paths="all"`.
- `[profile.dist-max] inherits="dist"`: `lto="fat"`, `codegen-units=1` — shipped `.app` staticlib + public WASM only (keep off PR builds; fat LTO without warm cache multiplies link time).
- `opt-level` is per-package-overridable (`[profile.dist.package.tree-sitter] opt-level=3`); `panic`/`lto` are workspace-wide.

| Target | Path |
|---|---|
| **macOS universal (FFI)** | Build on Mac/macOS CI: `cargo build --target {aarch64,x86_64}-apple-darwin` → `lipo -create` → optional `xcodebuild -create-xcframework`. `cross` has **no Darwin images** (Apple licensing). Set `MACOSX_DEPLOYMENT_TARGET` to match the app. Note: x86_64-apple-darwin demoted to Tier 2 in 1.90 — "tier 1 = safe" is stale folklore for Apple. |
| **Linux (old distros)** | `cargo-zigbuild` with pinned glibc suffix (`x86_64-unknown-linux-gnu.2.28`) so you control the floor, not your build host. Or `*-musl` for fully static. Dev tool, not a linked dep. |
| **WASM (browser)** | `wasm32-unknown-unknown` + wasm-bindgen + wasm-pack. **Pin wasm-bindgen crate == CLI version exactly.** |
| **WASM (server/remote)** | `wasm32-wasip1` (renamed from `wasm32-wasi`, dropped from stable in 1.84). `wasm32-wasip2` still experimental — don't ship on it. |
| **TUI / CLI** | Plain `cargo build`. |

**FFI panic decision:** lean **`panic=unwind` + `catch_unwind`** shims for the macOS GUI (don't crash the user's app); `panic=abort` is fine for the headless Linux/WASM remote where a supervisor restarts. `panic=abort` is silently ignored by the test harness and can't be set per-package.

**WASM size:** full stable ladder on the public profile (`opt-level="z"` + `lto=fat` + `codegen-units=1` + `panic=abort` + strip) then an **explicit `wasm-opt -Oz` step** (wasm-pack often disables the auto pass). Profile with `twiggy`. **Skip nightly tricks** (`-Zbuild-std`, `-Cpanic=immediate-abort`) — unstable, currently regressed (Sept 2025), ties you to nightly. **`wee_alloc` is dead** (archived Aug 2025, leaks) — use the default allocator.

**Reproducible builds (adopt now, free):** `rust-toolchain.toml` pin + `trim-paths` (default `"object"` in release; `"all"` for debuginfo) + `SOURCE_DATE_EPOCH` in CI. `tree-sitter` grammars compile C via `build.rs`/`cc` — a build-time C toolchain, gated behind `[target.'cfg(not(target_arch="wasm32"))'.dependencies]` + a feature, with a separate wasm highlighting strategy. Watch your 37 MB bundle / 16 MB exec cap; duplicate `-sys` crate versions are a *correctness* hazard (C one-definition-rule) — `cargo tree -d` + `[bans] multiple-versions = "deny"`.

## 8. Linting + CI quality gate

**Lint config in the manifest, not source** (`[workspace.lints]`, stable since 1.74). Members inherit via `lints.workspace = true`.

```toml
# root Cargo.toml
[workspace.lints.rust]
unsafe_code = "forbid"                       # every pure crate; FFI crate omits this
missing_docs = "warn"                        # ratchet to deny on the public API crate
rust_2024_compatibility = "warn"

[workspace.lints.clippy]
all = { level = "deny", priority = -1 }      # group needs LOWER priority so specifics win
pedantic = { level = "warn", priority = -1 }
# cherry-picked allows with reasons:
module_name_repetitions = "allow"
# no-panic enforcement in non-test code:
unwrap_used = "deny"
expect_used = "deny"
indexing_slicing = "deny"
panic = "deny"
# hygiene:
undocumented_unsafe_blocks = "deny"          # (on the FFI crate)
multiple_unsafe_ops_per_block = "deny"       # (on the FFI crate)
allow_attributes_without_reason = "warn"

[workspace.lints.rustdoc]
broken_intra_doc_links = "deny"
```

**Gotchas:** the `lint_groups_priority` lint that catches missing-priority is **broken in workspace manifests** (clippy #12729) — set priorities by hand. Mixing `workspace = true` with package-local lints in the same member is a **hard error** (cargo #13157) — the FFI crate must *not* inherit (it defines its own `unsafe_code = "deny"`). Use `#[expect(lint, reason="...")]` over `#[allow]` (stable 1.81) so suppressions self-report when stale.

**CI jobs** (separate, parallel; SHA-pin all third-party actions — `dtolnay/rust-toolchain`, `Swatinem/rust-cache`):
- `fmt`: `cargo fmt --check` (pin `style_edition` in `rustfmt.toml`; bare `rustfmt` defaults to 2015).
- `clippy`: `cargo clippy --all-targets --all-features -- -D warnings` (`-D` *after* `--` so it applies to your crate, not deps).
- `test`: `cargo nextest run --all-features --locked`.
- `docs`: `cargo doc` with `RUSTDOCFLAGS="-D warnings"` (plus the manifest `broken_intra_doc_links = "deny"` as the dependable hedge — RUSTDOCFLAGS doesn't escalate all categories).
- `msrv`: pin the 1.85 toolchain via `dtolnay/rust-toolchain@1.85`, `cargo check --all-features --locked`. Declaration without a CI check is a promise you can silently break.
- `feature-matrix`: at minimum `--no-default-features`, default, `--all-features`; plus `cargo check -p textview-wasm --target wasm32-unknown-unknown`. `cargo-hack` for powerset if the manual matrix gets unwieldy.
- `supply-chain`: `cargo deny check` (per-PR + daily cron) + `cargo audit`. `cargo-geiger --forbid-only` as a non-blocking unsafe-creep report.

These are **dev/CI tools, zero runtime supply-chain surface** — minimal-deps doesn't block them; they *enforce* it.

## 10. Open decisions (need the owner's call)

| # | Decision | Options | Recommendation | One-way door? |
|---|---|---|---|---|
| 1 | **FFI mechanism** | hand-written `extern "C"` + cbindgen · swift-bridge · uniffi | **Hand-written `extern "C"` + cbindgen** as primary: one small audited C surface serves Swift *and* the WASM/remote front-ends; no generated unsafe you can't audit per-line; keeps you sync. swift-bridge is bus-factor-1/pre-1.0 with self-declared quarterly breakage and **lacks slice/`Arc`/`Box<T>` support** (a direct hit for handing out borrowed buffer views); uniffi serializes complex types into a `RustBuffer` (you'd serialize twice). Middle path: prototype on swift-bridge to learn the shape, design a tool-agnostic coarse message boundary, drop to hand-written for shipping. **Defer final choice until the command-frame design settles.** | Soft — coarse boundary keeps it swappable |
| 2 | **mmap vs `forbid(unsafe_code)`** | safe seek+read · quarantined `textview-mmap` island · skip entirely | **Safe seek+buffered read for v1.** Quarantine mmap into a leaf crate **only if profiling** shows random-access GB reads need it. Profile on Apple Silicon + Linux, don't assume. | No |
| 3 | **LSP async route** | (a) hand-rolled sync JSON-RPC framing · (b) dedicated tokio I/O thread behind channels | **Route (a) for git/jq** (trivial, batch). **Spike both for LSP** — the one place the ecosystem is overwhelmingly async/tokio-first. Route (b) buys ecosystem leverage at the cost of tokio in the tree (feature-gated). Decide by measuring the sync hand-roll's complexity on a real server, not by reading. | Soft (feature-gated) |
| 4 | **Internal wire codec** | postcard · rkyv | **postcard** (the maintained bincode successor; smallest; sync; no unsafe). rkyv only if you measure a real need for zero-copy load of large session blobs — and its fast path is *unsafe* unchecked access, so untrusted bytes need the validated path. | No (versioned wire) |
| 5 | **Cross-language wire** | rmp-serde (MessagePack) · FlatBuffers · prost | **rmp-serde** first (serde-native, Swift+JS decoders, no codegen). Graduate one boundary to FlatBuffers/prost only if schemaless evolution across 3 languages proves error-prone. | No |
| 6 | **Error crate (core)** | std hand-rolled · thiserror · snafu | Start **std-only**, add **thiserror** when boilerplate hurts. **Don't adopt snafu on day one** — but note two production multi-crate cores (Iroh, GreptimeDB) moved to it for (a) multiple variants from the same source type (you *will* hit io::Error from page-read vs page-write) and (b) virtual-backtrace context without nightly. Re-evaluate after building 2-3 real subsystem enums. | No (thiserror non-breaking to drop) |
| 7 | **`panic` strategy at FFI** | unwind + catch_unwind · abort | **unwind + catch_unwind for the macOS GUI**; abort acceptable for supervised headless Linux/WASM. | Per-artifact |

| 9 | **`ropey` / `encoding_rs`** | adopt · defer | **Defer both** pending product scope. ropey only for real in-place GB-file editing; encoding_rs only if you can't declare "UTF-8 in, UTF-8 out" (and it costs binary size against your 16 MB exec cap). | No |
