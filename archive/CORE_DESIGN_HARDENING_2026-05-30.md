# Hardening Report — TextView reusable-core / Core↔UI boundary

## 1. Verdict

**The converged *shape* is sound; the *sequencing and scope* are not — do not commit to it as a program yet.** The sync in-process core API, per-doc serialization + COW snapshot reads, level-triggered subscriptions as the default, and "remote is a separate coarse state-sync seam, not an async core API" are all well-supported by the field (Zed/GPUI, CM6, Helix, Fleet/matklad) and are correct calls. I verified the load-bearing perf assumption holds: in-process value passing is COW-cheap (`EditorBuffer.swift:21` doc comment, `Tab.swift:50` content-out-of-Equatable), so the local seam the design worries about is the one genuinely free part.

But the design is being pressure-tested as if the decision to *build* it is settled, and it is not. Three caveats dominate everything below:

- **Caveat 1 — The expensive, irreversible commitments (Rust/FFI, wire freeze, capability handshake, optimistic-local) are all justified against four front-ends with zero lines of code, gated on a product-identity question the design itself leaves open (§2: "is the macOS app the product, or is the reusable core the product?").** Meanwhile the no-regret work everyone agrees on ships value regardless of that answer. Lead with the no-regret work; refuse the one-way doors until a second front-end has a committed customer.
- **Caveat 2 — Several converged claims are falsified by shipping code.** The domain/view ownership split (the keystone of "reconnect can't move your scroll") is contradicted by `SessionSnapshot.swift:42-58` persisting `viewMode`/`zoom`/`selectedTabIndex`/`wordWrap`/`sidebarExpandedPaths` as Core-owned durable state, and by `AutomationHost.swift:74-91` already commanding view via `automationGotoLine`. "Single-writer is a flip-a-switch policy" is false: it is baked into a document representation (`CodeMirrorBridge.swift:110-206`) with offset-based ranges and no element identity. "No new event types needed" contradicts matklad, whom the design cites. The split is a schema-v3 migration and a contract revision, not a description of today.
- **Caveat 3 — There is no ordering/causality contract, no threat model, and no observability seam — and all three are nearly free now and prohibitively expensive to retrofit into a serialized 4-front-end protocol.** STATE payloads carry no per-document version, replies carry no `clientSeq`, the remote WebSocket carries `runProcess`/PTY with the word "auth" appearing nowhere, and the core has zero structured logging today (deliberately avoids `os_log`).

**Net recommendation:** Reclassify this as two tracks. Track A (do now, no-regret, ships value): de-`@MainActor` the core, purge `NSColor`/`NSRange` from core value types, make content `(bytes, encoding, EOL)` not `String`, build the in-process push channel in pure Swift, and reserve `clientSeq`/version/correlation-id/`siteId` fields in the contract. Track B (the remote/Rust/multi-front-end vision): gate behind the §2 product decision and a committed second front-end. Do not start Track B's one-way doors pre-launch.

## 4. One-way doors (and the cheap insurance to take NOW)

| Door | Why it's expensive to reverse | Cheap insurance now |
|---|---|---|
| **Wire protocol freeze without identity/version fields** | Retrofitting `clientSeq`/per-doc-version/`siteId`/correlation-id into a serialized protocol consumed by 4 front-ends is a flag-day migration; there's no version negotiation to hang a transition on. | Reserve `clientSeq`, per-payload version, `siteId` (constant for now), and a correlation/causation id in every envelope from v1. Nearly free to reserve; the SessionSnapshot additive-optional convention is the existing template. |
| **Closed Codable enums on the wire** | Old peer crashes decoding a new variant; you can never add a command/event/topic additively. | Open tagged wire shape (`type` + opaque payload) with `unknown(...)` fallback. Rich typed enum stays in-proc only. |
| **UTF-16/NSRange in wire position types** | LSP could only *add* an optional encoding in 3.17 and must carry UTF-16 forever; Rust-core fights its native UTF-8 unit. | UTF-8 byte offsets as the wire-native unit now (or `positionEncoding` in the handshake). NSRange confined to the AppKit edge. |
| **Single-writer baked into the document representation** | Adding collab — or two Mac windows on one doc — becomes a CRDT/OT document-model rewrite touching every range-keyed consumer. | Carry `(siteId, clientSeq)` on every mutation now; allow N read-only view-clients per session; document "collab = rewrite" as a deliberate bet. |
| **Rust + UniFFI for doc-text hot paths** | Once the ABI is UniFFI-shaped, doc-text payloads are stuck at ~1,416 ns + multi-MB memcpy per call; the tier-1 near-free promise dies. | Don't start Rust until the Swift-on-Linux path is exhausted and measured. If Rust: opaque-handle (pointer+length) for doc text, swift-bridge/hand-owned ABI for blob-carrying calls, UniFFI only for scalars. Benchmark a 10MB string first. |
| **Remote transport without an auth model** | Retrofitting auth onto a shipped unauthenticated RCE endpoint is a one-way door. | Loopback-default + token/mTLS + Origin allowlist + SSH-as-safe-default, decided before any wire code. |
| **`runProcess` port without the trust gate** | Re-introduces SEC-001/002 RCE; the gate currently lives in a UI-side launcher being rewritten. | Trust gate is a mandatory property of the port contract + lsp.json-refusal regression test + Rust re-port checklist entry. |
| **Content modeled as `String`** | A lossy unit-of-content baked into the contract corrupts non-UTF-8/non-LF files on save. | Model content as `(bytes, encoding, eol)` from day one. |
| **No injectable clock + no correlation IDs** | Both are prohibitively expensive to retrofit into a serialized protocol + a callback delivery engine once clients depend on the envelope. | Inject `Scheduler`/`Clock`; bake correlation id into every envelope; per-session event log. Decide before any subscription/optimistic-local code. |
| **Per-doc as the only consistency unit** | Retrofitting cross-doc atomicity means re-deriving the global RW lock per-doc was chosen to avoid. | Worker-pool unit of work = "command against a SET of doc ids" (single = cardinality-1). |

## 5. If we publish (compat traps + minimum evolution machinery)

**Concrete traps** (each already present in the code, not hypothetical):

| Trap | Evidence | Why it bites a third party |
|---|---|---|
| No version negotiation | `MCPServer.swift:248-257` announces, never reads client version | No subset to agree on; only a flag-day upgrade works — impossible when you don't own both sides |
| Closed Codable enums | The recommended typed Command/Query/Event sum types | Old client crashes on a new variant; additive evolution is the cheapest lever and it's foreclosed at the type level |
| UTF-16/NSRange positions | `FindMatch.range` NSRange, `CMEdit.from/to` UTF-16 | Every non-JS client transcodes every position forever; you carry both encodings forever if you ever fix it |
| Three+ serialization surfaces | MCP catalog vs ScriptRunner DSL vs CM6 bridge (zero shared code) | The wire becomes a subset of what Mac actually does; third-party UIs are silently second-class |
| Monolithic Request/Reply enum | The `handle(_ req: Request) -> Reply` sketch | git can't version independently of LSP; closed-enum break hits the whole surface at once |
| Optimistic-local leaks domain logic into clients | §6 open thread asks exactly this | A third party must reverse-engineer the core's predict transform bug-for-bug or get flicker |
| `tools/call` returns stringified-JSON-in-a-text-block | `MCPProtocol.swift:262-275` | Reply types live only in stringly-typed JSON each client re-parses ad hoc; no schema to version |
| No reserved-field/deprecation discipline on the wire | `AutomationHost.swift:74-107` plain non-optional Codable structs | A rename silently breaks external readers; a later reuse of the name corrupts old clients |

**Minimum evolution machinery to design in now (even internal-only):**
1. **Mandatory version+capability handshake the server actually reads** (`min(common)`).
2. **Open-envelope/open-enum decode discipline** with `unknown(...)` fallback.
3. **Byte-offset-native positions** (or declared `positionEncoding`).
4. **One generated source-of-truth catalog** for all serialization surfaces + a CI drift check.
5. **Additive-only + reserved-names + deprecate-before-remove discipline** on the wire (the `SessionSnapshot` convention applied at the wire level — documentation + lint).

**Cost of keeping the door open vs closing it:** The five moves cost tens of lines + a lint/CI check + a doc convention *now*. Critically, **three of them (handshake, source-of-truth catalog, byte offsets) also improve the strictly-internal design** — the handshake protects Mac-UI-vs-remote-core skew, the catalog fixes the *already-observed* DSL/MCP drift, byte offsets ease the stated Rust port. So the marginal cost of "keep the door open" is small and partly negative. Closing the door (internal-only) saves a few weeks now but converts each skipped item into a flag-day migration later — and with no version negotiation to coordinate a flag day around, "later" is unusually expensive here. **Do items 1/3/4 anyway; treat 2/5 as cheap optionality. Defer all heavyweight publish machinery** (deprecation tooling, multi-version test matrices, conformance suites, published schema registry) until a second front-end is actually committed.

## 6. Performance reality (per-path honest cost)

| Path | Cost profile | Specific hot paths at risk |
|---|---|---|
| **Local in-proc (Swift Sendable values)** | **Essentially free.** COW value passing = refcount bump, tens of ns, payload-size-independent (`EditorBuffer.swift:21`, `Tab.swift:50`). MainActor hop = executor enqueue, low-single-digit µs, and tier-1 queries do no hop at all. A 1-slot coalescing mailbox is *cheaper* than the ~81 `@Published` properties' Combine fan-out. **This is where the design is correct and the local-boundary fear is unfounded.** | None — *provided* tier-1 reads run synchronously against a COW snapshot and don't bounce to the doc's serial executor (would add the very hop the design promises to avoid). Make that explicit in the read contract. |
| **Rust-FFI (UniFFI)** | **~1,416 ns noop floor; 10k structs ~12.8ms pure marshaling.** Every value serialized to a byte buffer. A 10MB `getDocument` or tab-snapshot = ~10MB alloc+memcpy *per call*. swift-bridge zero-copy: <1ns, 62,542 ns for the 1000-call case (~205-1000x faster). | `getDocument`, tab-array snapshot, `[HighlightRun]` retrieval (NSRange not Codable → per-run conversion pass on the hot highlight path), any per-frame/per-scroll query loop. **One-way door — the single most expensive decision in the design.** |
| **Remote WS + JSON-RPC** | Steady-state typing is RTT-bound (loopback 0.05-0.5ms / LAN 1-10ms / WAN 20-200ms) and optimistic-local hides ~70% of keystrokes (Mosh's measured figure). **The ~30% residual** (paste, autocomplete-accept, multi-cursor, IME) eats full RTT. **The bigger unquantified cost is non-delta traffic**: JSON-RPC string-escapes a 10MB doc to ~15-20MB on the wire; budget-expiry=hard-drop + reattach=clean-full-snapshot means a flaky WAN link triggers repeated full-doc reships. | Initial load + every reconnect resync (full doc); a naive tab-set state-topic push (serializes every open file's bytes on any tab change); large level-triggered coalescing payloads (git status on a monorepo). |

**Pre-existing per-keystroke ceiling (NOT added by the split):** `CMEditApplier.apply` does `Array(base.utf16)` (full O(N) UTF-16 materialize) + O(N) rebuild per debounce, and tree-sitter reparse (~0.2-0.3s for 25k lines) already runs off-main (`HighlightCacheActor.swift:73`). The split's worker-pool is a structural match for the existing off-main pattern — **highlighting does not regress.** The split's *new* trap is implementing "immutable snapshot" as a defensive copy, which doubles the rebuild churn; mandate COW-reference semantics to avoid it.

**Numbers found:** UniFFI noop 1,416 ns / 1000 calls 1.39ms / 10k structs 12.8ms; swift-bridge <1ns / 62,542 ns / ~205-1000x. RTT: loopback 0.05-0.5ms, LAN 1-10ms, WAN 20-200ms (~1ms/100km). Mosh: ~70% keystroke prediction, median response <5ms on hundreds-of-ms links. Tree-sitter: ~0.2-0.3s/25k lines, <100ms/10k-line C file.

## 7. Oversights / unknown-unknowns (no answer in the design yet)

- **Testing:** No injectable clock → coalescing/level-trigger/reconnect/reconcile are testable only via `Thread.sleep` + wall-clock (already self-annotated flaky). No language-neutral conformance suite — the "spec" is 1506 Swift-shaped `ViewerCoreTests` asserting NSRange/NSColor/Equatable-enum behavior that a Rust port can't run. CI is VM-bottlenecked (UI tiers VM-only per CLAUDE.md); a dual-language conformance suite multiplies that.
- **Observability:** Zero structured logging in the core (deliberately avoids `os_log`); no correlation IDs across client→command→worker→port→reply→delivery. A remote discrepancy is bisected by print statements over SSH.
- **Partial failure:** No model for hung sync ports (no timeout/cancellation), worker crash leaking the callback, half-open sockets (no heartbeat — tmux/mosh ship them), or in-flight-command-at-disconnect (the silent-data-loss seam).
- **Backpressure:** "Bounded buffer + budget" has no numbers, eviction policy, fairness, admission control, or reconnect-storm damping.
- **Session-state migration:** Live in-core session has no version/migration across a core upgrade — data-loss footgun on the Linux deployment.
- **Threat model:** None written down. Remote WS carries `runProcess`/PTY unauthenticated; the `runProcess` port erases the shipped SEC-001/002 RCE fix; capability scoping isn't authz; multi-session isolation is asserted not specified; reattach has no re-authn/session-binding.
- **Optimistic-local divergence:** No checksum/version on the reply to detect prediction divergence, no divergence-rate metric, no unconfirmed-prediction deadline, no lost-confirm recovery — silent corruption risk.
- **The meta-oversight (most consequential):** The §2 product-identity question ("is the macOS app the product, or is the reusable core the product?") is unanswered, yet the design's hardest, most-irreversible commitments are all justified against four front-ends with zero lines of code that the deliverability lens calls aspirational. The review hardened the *answers* while the *question that gates whether to build any of it* stays open.
- **Stale facts to correct in the design log:** "3 Combine-coupled core types" is wrong — only `SessionsCoordinator` imports Combine; the real blocker is `@MainActor` across 18 core files, an order-of-magnitude-larger and differently-aimed job. DocumentModel is ~2451 LOC, not ~2261. The optimistic-local "substrate already exists" claim is false — `CodeMirrorBridge.swift:205` is JS-side CM6 transaction hygiene, not a client/core predictor; remote prediction is ~0% built.

## 8. Recommended design adjustments (ordered)

1. **[do-now] Answer §2 first.** Is the macOS app the product or the reusable core? Refuse every Track-B one-way door until this is answered with a committed second-front-end customer. (R29, meta-oversight)
2. **[do-now] Fix the 172 prelaunch findings (S0 RCE + 3 silent-data-loss) and ship the macOS product.** The reusable-core work is marked SURFACE-ONLY / do-not-start-pre-launch by the team's own audit. (R29)
3. **[do-now] Sequence the extraction against branch reality** — land/abandon/freeze the 18+ feature branches and ~25 worktree-agent branches before starting a core extraction that touches every subsystem. (R28)
4. **[do-now] Reserve the identity/version/correlation fields in the contract envelope:** `clientSeq` (canonical edit envelope, not a remote afterthought), per-doc/per-payload version, `siteId` (constant), correlation/causation id. Promote `clientSeq` to a mandatory dedupe key. (R1, R6, R8, R9 — one field set holds open 4 doors: data-loss, multi-window, collab, debuggability)
5. **[do-now] Make content `(bytes, encoding, eol)`, not `String`.** No-regret; prevents byte-image corruption on save. (R18)
6. **[do-now] Purge `NSColor`/`NSRange`/`NSAttributedString` from core value types into portable Codable forms (UTF-8 byte offsets, RGBA); make error enums Codable.** No-regret for Linux *and* the wire. (R16)
7. **[do-now] De-`@MainActor` the core** (18 files, the actual months-long hazard — re-cost it; it is not "3 Combine types") without re-introducing the data races the annotation papered over. (Goal-fit, stale-fact)
8. **[do-now] Write the tier-classification contract + COW-snapshot mandate + debug timing assertion (~100µs)** into the CoreEngine read contract. Snapshot = COW reference, never a defensive copy. (R22, R23)
9. **[do-now] Build the in-process push channel in pure Swift first** — net-new (MCP contributes only framing + value types + verb catalog), with the worker pool, per-doc serialization, reply/notification multiplexing, and per-session budgets. (R7, R11, R12)
10. **[do-now] Inject a `Scheduler`/`Clock` port and bake correlation IDs + a per-session event log** before any subscription/optimistic-local code. Model subscription delivery as a pure function. (R9)
11. **[do-now] Collapse the 3 serialization surfaces to one generated catalog + CI drift check; reconcile `declare(caps)` with the existing `PluginGrantStore` authz before inventing a third vocabulary.** (R15, R17, R19)
12. **[do-now] Produce the per-field domain/view/shared-view-intent classification table** for every `SessionSnapshot`/`AutomationState` field; move view-state into a separate sub-record; add the authoritative Core→client reveal path + reconnect precedence rule. (R5)
13. **[do-now] Define the worker-pool unit of work as a SET of doc ids** (keeps cross-doc atomicity reachable). (R20)
14. **[before-remote] Write the threat model.** Loopback-default + token/mTLS + Origin allowlist + SSH-as-safe-default; make the `runProcess` port's trust gate (SEC-001/002) mandatory with a regression test; redaction policy for error `reason`; per-session isolation inventory; reattach re-authn + transfer authorization. (R2, R3, R21, R26, R28-isolation)
15. **[before-remote] Define the disconnect-mid-edit contract, the partial-failure taxonomy (deadlines/cancellation/heartbeat/supervisor), backpressure numbers, and the optimistic-local reconcile contract** (authoritative-hash-on-reply, divergence metric, prediction deadline, idempotency-key recovery). Specify the open wire envelope + version handshake. Carve doc-text out of level-triggered state topics into a versioned delta stream. (R8, R10, R11, R13, R14)
16. **[before-remote] Handle IME marked-text and assistive-tech text access** at the seam (or explicitly await-confirm IME). (R27)
17. **[before-rust] Exhaust and MEASURE the Swift-on-Linux headless path first** (steps 5-9 are its prerequisites anyway). Only spike Rust if Swift-on-Linux proves inadequate on a measured axis. (Goal-fit visions 4-5, R24, R4)
18. **[before-rust] Hand-write the flat Rust enum and prove a 1:1 mapping; spike a closure-based subscription + payload error enum across the chosen bridge; deliver a full signed universal `.app` from the first spike** (the size/signing blind spot is invisible to `swift build`/`swift test`). Decide uniffi-vs-hand-owned-ABI with the owner; mandate opaque-handle for doc-text; benchmark a 10MB string through both bridges. (R4, R24, plus the signing/size and divergence-suite findings)
19. **[before-publish] Add reserved-field/deprecation discipline, per-subsystem namespacing of the protocol, typed (open-form) reply payloads, and the live-session migration/version story.** Defer the heavyweight publish machinery (multi-version matrices, conformance registry) until a second front-end is committed. (R13, R14, R25, §5)

**Where the design is genuinely strong (keep as-is):** the sync in-process core API for local front-ends; per-doc serialization + concurrent COW snapshot reads; level-triggered as the *default* push semantics (the diagnostics store already works this way, `LSPDiagnosticsStore.swift:8-29`); treating remote as a separate coarse state-sync seam rather than an async core API; the in-proc fast-path (Option C) passing Sendable values and skipping JSON. These are the load-bearing assumptions that hold up — the local boundary is the one genuinely free part, and the design correctly does not stretch a sync-blocking boundary over the network.
